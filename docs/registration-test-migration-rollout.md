# 注册重构测试、迁移、投产与验证方案

## 1. 测试分层

### 单元测试

覆盖：

- 页面状态识别和合法转移。
- 检查点单向推进。
- Protocol 成功、失败和 Roxy fallback。
- Session 退出态提前结束。
- OTP 已验证页面禁止 resend。
- 错误分类、可重试性和 next_action。
- 资源租约释放条件。

### 流程回放测试

使用现有日志构造固定场景，不连接外部服务：

1. 正常 Roxy + Protocol 混合成功。
2. 邮箱提交导航长阻塞。
3. 密码页已到达但 URL 未及时变化。
4. 邮箱已验证但没有 resend 按钮。
5. OAuth callback 错误后退出态。
6. 2FA Protocol 失败后 Roxy fallback。
7. Token 获取后后处理失败。
8. Roxy Profile open 首次超时后重试。

### 并发和存储测试

- 多 worker 同时更新同一批次。
- 同一 Attempt 重试互斥。
- 投影重复消费事件。
- 投影失败后重试。
- 进程在每个不可逆检查点中断。
- 数据库重启恢复。

### 真实链路验收

所有回放和集成测试通过后，才允许跑一个受控真实任务。真实任务只验证新埋点、状态机和投影，不用于探索未知流程。

## 2. 数据库迁移

迁移必须使用独立开发数据库，执行：

```text
备份/快照
  -> dry-run
  -> additive migration
  -> backfill
  -> row/count/index verify
  -> replay tests
```

禁止：

- 连接生产库验证未完成的存储代码。
- 删除旧表。
- 重排历史 ID。
- 用根目录 JSON/TXT 回写数据库。
- 在同一个提交中混合大规模业务重构和数据迁移。

迁移校验至少包括：

- `registration_jobs` 行数和 ID 不变。
- Attempt 与 Job 一对多关系完整。
- 账号、邮箱、代理租约无孤儿记录。
- 已终态任务不会出现活跃租约。
- 历史任务可读取。
- 重复执行迁移不会产生重复数据。

## 3. 投产策略

### 阶段 A：影子观测

- 仍使用旧执行结果。
- 只写新事件、耗时和投影对照数据。
- 不改变邮箱、代理、账号状态。

### 阶段 B：单任务 Roxy 灰度

- 只允许一个 worker。
- `ENABLE_CODEX_AUTO=False` 保持不变。
- 2FA 使用现有 Protocol 优先、Roxy fallback。
- 人工查看完整诊断和事件链。

### 阶段 C：小批量灰度

- 2～3 个任务。
- 观察成功率、p50/p95、Session 提前结束、后处理补跑和投影一致性。
- 不立即扩大并发。

### 阶段 D：恢复常规并发

- 逐步恢复原 workers。
- 观察至少一个完整批次。
- 通过后才允许扩大批量。

## 4. 回滚方案

回滚顺序：

1. 关闭新编排器 feature flag，恢复旧执行入口。
2. 保留新产生的 Attempt、Run、Event，不删除。
3. 停止新投影 worker，使用旧投影或只读展示。
4. 如迁移只增加字段，不执行破坏性回滚。
5. 对已越过不可逆边界的任务进入人工对账，不重新注册。

任何回滚都不得：

- 把已创建账号的邮箱改回可用。
- 删除账号或 Token。
- 重新领取已经占用的邮箱。
- 用旧快照覆盖新状态。

## 5. 投产验收指标

功能：

- 正常任务成功。
- 部分成功可以补跑 2FA/Codex/套餐。
- 未知状态进入恢复或人工对账。
- 不发生重复注册。

性能：

- 当前普通流程中位数约 3 分 38 秒，程序侧减少 30～60 秒。
- Session 退出态不再固定等待 120 秒。
- 邮箱提交不出现重复长等待。
- p95 不被 fallback 叠加拉长。

稳定性：

- 并发更新批次无死锁。
- 投影失败不影响注册事实。
- Roxy Profile、代理和邮箱租约最终收口。

诊断：

- 所有失败、部分成功、后处理失败都有现场。
- 诊断邮箱与任务、Attempt、邮箱池记录一致。
- 不做脱敏，但采集不能阻塞主流程。
