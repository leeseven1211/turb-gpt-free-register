#4681/#4682 共用 Attempt #137093。全量浏览器捕获分别为 93 和 86 条事件、零丢失；仅观察到 session/CSRF GET，没有 `/api/auth/signin/openai` POST，也没有账号创建 POST。#4681 已失败，#4682 在认证跳转阶段暂停后到期失败，均未创建本地账号。两次失败仍保留在 Attempt 上的提交事实起初错误地把 signin POST `dispatch_intent` 写在 CSRF GET 之前；重试投影又只在 `request_unknown/manual_reconcile` 分支检查围栏，普通 `failed` 因此显示可重试，实际执行才被存储层拒绝。

当前修复将 CSRF GET 与 signin POST 拆成两次同页脚本调用：GET 成功后才持久化 signin POST 派发意图；CSRF token 只在本次 WebDriver 调用间传递，不进入日志、数据库或页面全局对象。所有无账号的注册重试状态现在都核对相同 Attempt 的未决提交，未决或事实读取失败时拒绝派发并说明原因。旧 Attempt 保留失败现场，不通过手改数据库消除围栏；剩余真实验收从新的单任务开始。新增回归以隔离 PostgreSQL 验证重试投影，并用 Node 执行两段浏览器脚本，确认请求顺序为 CSRF GET 后 signin POST。

## 进度展示修复

保留“登录与身份验证”主步骤，在其中按真实发生顺序保留页面、邮箱提交、认证跳转、密码和验证码子阶段；不同阶段的实例不再互相覆盖开始时间、完成时间或耗时。主步骤需要明确的验证完成或登录会话证据，所有已开始的子阶段也应有收口结果。

事件发生时间与阶段开始时间分开保存和显示。详情先展示各子步骤，再展示中文阶段事件；“开始”和“完成”各是一条事件，不再将事件条数称为重试次数。详情中的“已记录阶段”来自实际事件，模板包含的未执行阶段不会被列成执行事实。Run 和线路归属过滤保持原有规则。

真实 WebUI 验收又发现同一阶段的多条 `running` 消息共用开始时间。第二轮修复将每次转换的 `occurred_at` 单独持久化并贯穿事件投影；已由 OTP 完成的认证步骤不再被后续 Token 时刻延长。#4668 认证耗时回查为 146 秒，结束于 17:26:23。旧记录缺少独立发生时间时不能通过修改显示制造新事实；终态收口、进程恢复和迟到回调的时间边界继续纳入核验。
