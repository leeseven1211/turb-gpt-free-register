# 批量任务平台实施与验收

日期：2026-11-10。开发分支：`codex/bulk-task-platform`。本文记录实现和隔离验收，Git 合并、推送及部署状态以实际交付回执为准。

## 已实现

- 新增一级菜单「批量任务」，包含批次列表、新建和详情。支持查询套餐、补密码、补 2FA、补 Codex、组合补全。
- 与账号列表共用查询规范和列筛选组件，保持创建日期、归档、优惠等既有语义。账号列表可带入当前筛选或勾选账号。
- 支持查询匹配、显式 ID、原批固定账号三种来源。预览在同一数据库快照固定名单及执行配置，准备过程在后台运行；创建批次快速返回回执，不同步提交全部 Run。
- 后台有界展开、集合提交、账号占用退避、跨进程领取及 fence；使用既有数据库许可执行，全局、动作类型和本批并发上限同时生效。
- 首轮、同批重跑轮与当前结果分离。按失败、部分成功、待确认、未执行、取消或勾选成员重跑；保留每轮归属的父、子和续接 Run。
- 增量统计、错误分类、功能结果和逐项执行详情。套餐成功证据与旧缓存分开，账号数量与国家查询项分别统计；历史条件不足时不推断优惠变化。
- 取消未开始、协作停止、同名单再次执行、复制条件新建、断网后找回回执。旧任务中心受管任务的人工重跑进入同批新轮，并复用幂等请求身份。
- 持久 outbox、组合补全依赖修复、异常投影隔离、过期预览维护、受管历史保留。三类协调 worker 纳入就绪检查，部分线程退出可补起。

核心代码位于 `core/bulk_operations/` 与 `core/storage/operations/bulk*.py`，HTTP 边界为 `webui/routes/bulk.py`，页面为 `webui/static/js/pages/bulk/page.js`。复用现有 `operation_batches/tasks/runs`，新增八张关系表，不引入 Redis、独立消息中间件或无限线程队列。

## 既有热点

账号任务中心普通列表先确定当前页，再读取该页有效 Run；准确的全局 facets 和 Run 相关筛选仍保留其全范围计算成本。凭证刷新和手动上传改用精确定位，消除逐账号全库凭证扫描。满载调度同池容量每轮读取一次，64 个候选的等待观察使用一次集合事务，相同原因不重复写入。细节与测量见[既有热点实施记录](performance-implementation.md)。

没有按最初草案新增任务中心持久 current-Run 读模型：最终采用已验证等价的分阶段查询，保留活跃 Run 优先和兼容来源时间规则。批量平台的统计读模型仍完整落地。此选择避免在兼容来源尚多时引入没有覆盖全部更新路径的派生状态。

## 验证方式

全部数据库验证使用独立 `turb_test` 和随机 `test_` schema，不读取生产账号，不调用外部账号服务。真实浏览器连接独立测试服务；只启动批量协调线程，执行结果由合成 Run 回执注入，不启动真实业务 dispatcher。

已完成的回归批次如下，计数存在覆盖重叠，不相加当作唯一测试数：

- 新批量模块、账号筛选与读取、worker 就绪、发布检查联合：107 项和 79 个子用例通过。
- 补充 HTTP 契约与旧任务重跑幂等：10 项和 3 个子用例通过；同一请求两次返回同一轮，首轮加唯一重跑轮共两轮。非法结果字段或超出长度、数量限制的原因筛选在受理前拒绝，不生成必定失败的新轮。
- Run 仓储、准入、dispatcher、组合补全与续接、Codex、Token 刷新、Sub2API 等 15 个领域文件：204 项和 63 个子用例通过。
- 前端查询语义、回执恢复、超过 40 轮的连续分页、旧任务重跑幂等、五类功能中文统计、账号列筛选与任务日志：60 项通过。
- 满载集合观察及周边并发：16 项通过；64 与 8 个候选使用相同固定 SQL 预算（上限 12），原因未变时零 DML，每 15 秒最多一次集合续期。
- 最终接口、worker、查询及发布检查：23 项和 6 个子用例通过；套餐比较与存储 28 项和 16 个子用例通过；历史轮未物化取消成员另增 2 项通过。
- 固定名单的集合触发器另有 4 项真实数据库验证，覆盖从旧逐行触发器迁移、重复初始化、身份变更拒绝、多行整句回滚及合法投影更新。51 个 Python 源文件静态检查、10 个脚本语法、Jinja 模板与文档链接检查通过。

浏览器验收使用 35 个合成账号：首轮 32 成功、3 失败；按失败重跑 3 个后，当前结果 35 成功、0 失败，首轮仍保留 3 失败。失败统计可筛出对应明细，查看执行可打开精确 Run。复用固定名单创建新批后取消，35 个目标全部正确显示已取消；390 像素视口无横向溢出，最终页面控制台零错误。截图与原始响应属于本地验收产物，不提交账号或凭据材料。

## 性能口径

`tools/benchmarks/benchmark_bulk.py` 可复现选择、受理、集合提交和读取测量；默认种子为 10 万合成账号、100 万 Task 与同量 Run，每项 30 样本。合成历史分段提交，脚本在结束后清理自己的测试 schema。未执行任何外部请求。

最终完整规模测量如下，均为 30 个样本；[原始合成测量结果](benchmark-bulk-final.json)随文保存。

| 路径 | p50 毫秒 | p95 毫秒 | 客户端 SQL 数 |
|---|---:|---:|---:|
| 500 目标固定名单与预检 | 140.6 | 441.6 | 14 |
| 500 目标创建批次 | 11.2 | 15.8 | 8 |
| 10,000 目标固定名单与预检 | 2095.2 | 3373.5 | 19 |
| 10,000 目标创建批次 | 10.3 | 15.9 | 8 |
| 100 目标集合提交 | 232.3 | 276.0 | 28 |
| 10,000 目标汇总读取 | 10.1 | 13.5 | 4 |
| 10,000 目标内 50 条明细 | 6.6 | 9.2 | 3 |

固定名单与预检由后台执行，页面先返回准备回执。预检每块最多 5000 个目标，仅读必要资格字段；冻结保护改为语句级集合触发器，避免每目标内部读取名单状态。优化前相同数据规模的 1 万目标预检为 509 条客户端 SQL、p95 10.3 秒，最终降至 19 条、3.4 秒；仍未达到初始设计的 2 秒预检目标，保留为明确差距。客户端 SQL 计数不包含触发器内部语句，不能仅凭计数代替时间测量。

测量是本机共享 PostgreSQL 的数据库与本地提交成本，不包含真实网络、代理、验证码或账号远端耗时，也不代表 Oracle 的实测。更早一次大规模验收期间共享 Docker/PostgreSQL 服务退出，恢复原服务后重跑完成；没有证据把退出原因归于某个查询。
