# 批量任务：界面、迁移与交付验收详细设计

日期：2026-11-10。状态：实施设计，尚未修改业务代码或部署。

本篇细化[详细设计入口](detailed-design.md)与[总体方案](design.md)的页面状态、交互、代码分工、发布门槛和验收案例。
配套阅读：[数据与事务](data-and-transactions.md)、[接口与领域适配](api-and-adapters.md)、[性能与运行](performance-and-operations.md)。
数据结构、事务及恢复规则由数据分篇定义；HTTP 字段与领域适配由接口分篇定义。
本篇不新增另一套任务状态，也不通过前端猜测远端结果。

## 1. 本次交付的完整范围

必需功能是查询套餐、补密码、补 2FA、补 Codex，以及复用现有规划器的组合补全。
每个功能均须具备创建、固定目标、批次详情、结果统计、失败处理和执行详情跳转。
查询套餐只是首条纵向验证链路；完成它不能宣布本次需求全部交付。
性能、恢复、旧入口兼容、本地与 Oracle 的分别验收属于完整交付的一部分。
不要求第一版同时重做提链支付、所有邮箱资产操作、CPA 导出或注册主流程。
这些模块的批次概览可渐进接入，涉及业务行为改变时另列具体方案。

以下语义在所有页面保持一致：

- 日期就是当前账号列表“创建 / 更新”列的创建日期条件，结束日包含在内。
- 日期不改称已经验证的远端注册日期，也不独自增加时区换算。
- “无优惠”沿用当前列表列筛选，包括其保留历史成功结果的既有行为。
- 密码“有/无”、2FA、Codex 等现有列条件保持原义，不能暗中改为确认状态。
- 预检资格独立显示，不能改变已经匹配和固定的目标集合。
- 排序第一版沿用账号列表的 `id DESC`；“最多 N 个”使用同一排序。
- 功能参数只展示目录声明的能力；现有配置快照中的值默认只读。
- 同批失败重跑生成新轮次；复制条件才创建新批次。

## 2. 菜单、路由与上下文

### 2.1 菜单职责

| 菜单 | 内容 | 与批量任务的连接 |
|---|---|---|
| 账号 | 当前资产、列筛选、选择和单条快捷动作 | 带入当前筛选或显式已选 ID |
| 批量任务 | 用户批次、固定目标、执行轮次、结果与控制 | 新增一级入口，默认批次列表 |
| 任务中心 | 逻辑任务、具体 Run、阶段、日志和诊断 | 显示所属批次，返回原轮次视图 |
| 提链工作台 | 平台材料、支付、到账等专用交互 | 后续链接同一批次身份，保持专页 |

一级菜单放在“任务中心”之前，使用现有侧栏、图标与活动态样式。
菜单只提供“批次列表”和“新建批次”两个固定子入口；详情由具体批次进入。
手机沿用现有折叠侧栏；不再增加独立底部导航或第二套页面外壳。
本地与 Oracle 的批次仅属于当前部署，不显示不存在的跨部署汇总。

### 2.2 可恢复导航状态

建议导航表示为 `bulk/list`、`bulk/create`、`bulk/detail`，实体和视图放查询参数。
详情状态包含 `batch_id`、`view=current|round`、`round_id`、结果筛选和分页游标。
这些参数是导航设计，实际 URL 编码由扩展后的现有导航模块统一生成和解析。
新 API 的十进制 ID 作为字符串传递，不使用 `Number()` 转换数据库大整数。
进入原 Run 详情时保存返回位置，关闭后恢复批次、轮次、筛选、滚动和焦点。
刷新、浏览器前进/后退、复制深链接都必须重新取得同一实体。
无效批次显示“批次不存在或已清理”，保留返回列表入口，不回落到其他批次。
旧 `#accounts`、`#tasks` 等导航继续有效，不能因引入实体路由全部失效。

## 3. 批次列表

### 3.1 固定布局

顶部为标题、刷新按钮及唯一主要动作“新建批次”。
筛选只有功能、批次状态、创建日期、名称/批次号；默认每页 20 条。
列表读取公共摘要，不逐批加载明细、Run、事件或功能完整结果。

| 列 | 必需展示 | 小屏处理 |
|---|---|---|
| 批次 | 名称、ID、功能 | 保留，名称允许换行 |
| 范围 | 条件摘要或已选账号数 | 折叠详情，保留目标数 |
| 状态 | 准备中、执行中、停止中、已结束等 | 保留文字，颜色仅辅助 |
| 进度 | 当前结果已结束 / 固定目标 | 保留 |
| 结果 | 成功、部分成功、失败、未执行等摘要 | 优先保留失败与待确认 |
| 时间 | 创建时间、结束时间或已用时间 | 次要行展示 |
| 轮次 | 首轮/最近重跑轮，当前视图标识 | 次要行展示 |
| 操作 | 查看、复制条件；控制放更多菜单 | 主要入口可直接触达 |

“已结束”不是“全部成功”，应显示“已结束 · 失败 12”等结果。
尚有新轮准备请求时显示“正在准备重跑”，旧当前结果继续显示并注明未切换。
批次列表不在每次轮询重新按更新时间排序，使用稳定创建顺序。
新批次出现时提示“有新批次”，主动刷新后进入；用户刚创建的批次可直接打开。
点击失败数量进入该批次“当前结果”的失败筛选，而不是全站任务失败列表。
首屏无数据、筛选无匹配、初次加载失败分别显示不同文案和操作。
刷新失败保留上次有效列表，显示更新时间及可重试状态，不清空已有内容。

## 4. 新建批次

### 4.1 页面结构

采用完整页面，避免在现有任务详情上再叠多层弹窗。
桌面主区按“操作 → 范围 → 预览 → 执行设置”组织，旁边显示紧凑摘要。
小屏同顺序纵向排列，摘要位于提交按钮之前；不形成嵌套滚动容器。
表单保留用户已填值；切换功能只改变功能参数和推荐条件的显示顺序。
所有合法通用条件继续可用，不因为功能推荐而偷偷增删筛选。

### 4.2 操作与参数

| 字段 | 规则 |
|---|---|
| 操作 | 查询套餐、补密码、补 2FA、补 Codex、组合补全 |
| 批次名称 | 可选，默认按功能和时间生成；保存前后可识别同一批次 |
| 功能可用性 | 目录提供，展示具体缺少配置/当前部署不支持的原因 |
| 有效执行设置 | 展示即将捕获的已有配置及修订，不展示密钥 |
| 可覆盖参数 | 仅渲染目录明确声明可覆盖且 service 已支持的字段 |
| 本批并发上限 | 正整数，受目录与服务器策略校验，不等于实际线程数 |

查套餐国家、自动刷新 AT、补密码驱动等当前来自全局配置快照，第一版只读展示。
不能只在新页面加国家下拉框，然后让执行器忽略它或临时改全局配置。
Codex 已支持的驱动覆盖等能力经目录声明后可以编辑，按实际公开契约校验。
组合补全显示现有规划器计划涉及的能力，不提供任意拖拽步骤或重新排序。
参数变化或生效配置变化时，重新预览并显示新的固定时点和范围，不沿用旧参数的资格摘要。

### 4.3 目标来源

| 来源 | 提交内容 | 页面说明 |
|---|---|---|
| 按当前条件 | 规范 `AccountQuerySpec` | 所有匹配结果，与当前页无关 |
| 账号页已选 | 显式 ID 集合或服务端选择引用 | 本页/跨页已选数量明确可见 |
| 原批固定账号 | `source.kind=batch_targets`，全部成员、显式目标或指定视图结果子集 | 与重新按条件筛选区别展示 |

三种来源互斥，不能同时发送过滤条件和当前页账号来猜选择意图。
账号页提供“按当前筛选创建批次”，不要求先跨页勾选全部账号。
原查套餐、补密码等已选快捷动作预填功能和显式 ID，减少重复输入。
跨页显式选择继续遵守现有选择规则，切换筛选时提示已选范围而非静默覆盖。
“全部匹配”与“最多 N 个”是处理范围选项，不是并发设置。
最多 N 个取当前列表同样的 `id DESC` 前 N 项，摘要明确写出排序。
输入 N 只限制固定目标，不改变筛选条件；目标固定后本批人数必须精确。
全部匹配数按需统计；未返回时显示“本批已固定 500 个，最多 500”，不虚报全体数量。
只有服务端明确返回同一固定快照的完整匹配数，才显示“匹配 2,000，本批 500”。
后来另行统计的数量必须标统计时点，不与原选择快照混写；估计值不得冒充精确值。

### 4.4 共享列筛选组件

抽取共享字段目录、值编码、显示标签、清空操作和规范查询对象。
账号列表表头和批次表单是两种宿主，同一字段使用同一个状态与序列化契约。
现有 `accountListQueryParams()` 先通过兼容适配器输出该契约，不删除旧 API 参数。
保留邮箱/姓名搜索与高级搜索 `q` 的区别，不把两者合并造成集合变化。
归档、套餐以及隐式旧开关先显式归一化到查询对象，再带入批次页面。
同列多选 OR、不同列 AND，空值、清筛、未知枚举的处理两处完全一致。
日期控件标签沿用“创建日期”，显示与账号列相同的开始/结束日。
优惠“无优惠”直接复用原谓词；最近失败仍保留旧无优惠的账号必须继续匹配。
若新增“最近查询状态”“确认状态”，须同时加入列表与批次目录及集合对照测试。
功能推荐条件只改变展示顺序和提示，不改变实际查询对象。
服务端返回合法枚举；旧值暂时无匹配时仍保留已选值，避免刷新选项清掉条件。
条件摘要可逐项移除，清空后两处序列化结果一致；不另建第二套 SQL 拼装器。
从批次“查看相同筛选”进入账号页时使用查询对象；“查看本批账号”使用固定名单。

### 4.5 预览状态机

| 状态 | 内容与可用动作 | 创建按钮 |
|---|---|---|
| 未预览 | 条件表单、范围摘要 | 禁用，提示先固定范围 |
| 正在受理预览 | 100 毫秒内显示准备提示 | 禁用 |
| preparing | 固定范围尚未完成，显示准备时间 | 禁用，不编造最终数量/百分比 |
| ready | 固定数量、时点、资格摘要、分页样本 | 条件与参数有效时启用 |
| failed | 分类原因、重试准备；保留条件 | 禁用 |
| expired | 原快照已过期，重新预览 | 禁用 |
| consumed | 已创建批次的链接 | 打开原批次 |
| 条件已变更 | 原结果保留作参考并标失效 | 禁用直到新预览 ready |

预览只读取本地事实，不发认证、套餐、代理或邮箱网络请求，不占用账号执行名额。
ready 后显示固定时点、目标数、可提交、等待账号、材料不足、已废/已删除等资格摘要。
所有资格计数都属于固定目标，不能从目标数里偷偷扣掉等待或不符合项。
只有功能整体不可用、请求非法或目标为零等全局条件阻止创建。
全部账号暂时占用时仍允许可靠受理并等待；个别资格失败不拒绝整批。
样本默认 20 条并支持分页，不把完整账号、Token、密码或全部结果带到浏览器。
修改名称或本批并发不改变目标；修改查询、来源、数量限制或选择实体使预览失效。
切换功能须重新核对目录/预检版本；可以保留合法查询值，但不能复用不兼容资格摘要。
预览条件变化时取消旧请求或丢弃其响应，旧 ready 不能覆盖新输入。
重新预览显式生成新时点和数量，原选择只在未消费时按 TTL 清理。

### 4.6 创建与回执

创建请求引用 ready selection、功能参数、用户已见的 `expected_config_revision` 和稳定幂等键。
点击后立即禁用重复提交并显示“正在创建批次”，页面其余内容保持可读。
202 后进入批次详情，文案为“批次已受理”，不显示“全部账号已入队”。
创建只消费快照，不同步创建所有业务任务；详情显示待提交和后台展开进度。
创建超时或网络断开时保留幂等键与请求摘要，通过同键重发/查询找回原批次。
回执不明不能自动换键重发；用户主动新意图与同一次网络重试必须明确区分。
相同键但内容不同显示冲突并定位修改项，不把冲突当成功或生成第二批。
401 引导重新登录并保留草稿；登录恢复后先找回原请求，不盲目重建。
功能配置在提交前变化时返回 `409/config_revision_changed`；保留原 selection 作参考，展示新设置并重新预览后再次提交。
页面显示新旧配置修订与受影响公开字段，不自动捕获用户尚未见过的新版配置并运行。
明确 409 未受理不占成功幂等键；更改设置后可用新键提交，回执不明仍必须用原键找回。

## 5. 批次详情与轮次

### 5.1 视图选择

默认“当前结果”，旁边提供“首轮”“重跑 1”“重跑 2”等选择。
当前结果以原批固定目标为分母，每账号取最近已固定成员轮次的结果。
轮次视图以该轮固定成员为分母，只显示该轮拥有的 Run/依赖执行。
重跑准备尚未冻结完成时，当前结果仍保持旧归属，并显示独立准备请求提示。
冻结提交后对应目标转入新轮待提交，不能同时计入旧失败和新排队。
新轮出现不自动把正在阅读的首轮视图切走；只提示可查看新轮。
人工单条重跑新管理任务同样生成单成员轮，任务中心入口也显示此归属。
自动依赖续接沿用当前轮，不能显示成用户又发起一次重跑。

### 5.2 摘要与公共统计

顶部显示名称、功能、范围固定时点、条件、有效设置、批次控制状态和轮次。
主要区域为进度、公共统计、功能结果、账号明细；设置和历史默认折叠。
公共统计读取后端互斥桶，前端不重新从当前页计算全批总数。
目标数等于待提交、等待账号、排队、执行/外部等待、成功、部分成功、失败、未执行、取消、待确认之和。
“已结束”采用后端明确口径，不能自行把等待外部结果计为结束。
展示“已结束 / 本视图目标”，成功率另标明确分母；跳过不能抬高执行成功率。
协调收尾、结果投影未到最终修订时显示“结果汇总中”，不能提前宣告结束。
摘要附 `summary_revision` 和更新时间；投影延迟时显示同步状态并保留已知数字。
摘要与明细携带视图/轮次标识，不把上一轮迟到的数字拼到新轮页面。
原 Run 补齐真实回执后可修订原轮结果，界面标结果修订，不能宣称历史永不变化。

示例：首轮 100 个账号中失败 10 个，重跑后成功 8、失败 2。
首轮仍显示本轮失败 10；重跑 1 显示目标 10、成功 8、失败 2。
当前结果显示目标 100、失败 2、重跑恢复 8，不把总目标变成 110。

### 5.3 功能结果面板

| 功能 | 必需统计 | 必需边界 |
|---|---|---|
| 查询套餐 | 本次成功/部分国家成功/失败；套餐与 Plus 优惠分布 | 本次成功无优惠属于成功，旧优惠不冒充本次结果 |
| 补密码 | 本轮已确认、明确新设置、明确验证已有值、未执行、失败 | 仅本地有值不等于本轮确认；证据不足不猜设置方式 |
| 补 2FA | 本轮确认、明确新启用、原本满足、未执行、失败 | 启用标志、材料完整、远端确认分别表达 |
| 补 Codex | 本轮可用凭证确认、回执待确认、失败 | 旧凭证仍可用不代表本轮成功 |
| 组合补全 | 账号总结果；密码/2FA/Codex/AT/套餐各能力结果 | 父 Run 临时 partial 不代表账号结束；等待子任务保持活动 |

套餐按账号统计与按国家查询项统计分区标注，国家项合计允许大于账号数。
“所有所选国家无优惠”必须每国均成功；部分国家成功只能报告已获得的证据。
前后变化仅比较同产品、同国家范围、可靠基线；无基线显示“不可比较”。
历史筛选“无优惠”和本次结果“无优惠”是不同阶段，标签与统计来源不能混淆。
密码或 2FA 只知道确认成功时显示“已确认，变更方式未记录”，不根据字段变化猜测。
功能面板使用受控组件注册；公共页面不为每个功能复制完整模板和轮询代码。

### 5.4 明细与诊断

明细公共列为账号、状态、当前阶段、结果摘要、错误分类、耗时和查看执行。
每功能仅增加必要列，完整结果按需打开；默认每页 50 条，游标分页。
点击统计桶/错误分类设置明细过滤条件，保留当前轮次，不重新筛选原账号条件。
“查看执行”打开明确 owned Run；组合任务提供父/子执行入口与步骤名。
等待账号占用可查看阻塞任务，但必须标“其他执行”，不能计为本批成功。
账号删除后显示保存的身份快照和 account_missing，不使整行消失。
失败全文可展开；分类、阶段与实际证据同时可见，不新增“未分类”兜底。
新原因码未被旧前端识别时显示服务器中文分类，保留原因码，不吞成通用失败。
批量选择基于目标引用，不基于 DOM 行号，翻页/刷新后仍能精确定位。

## 6. 重跑与批次控制

### 6.1 重跑未成功

操作面板明确来源为“当前结果”或某一轮，再选择失败、部分成功、待确认、未执行、取消等服务器允许项。
默认“失败”是否包含中断由服务端映射决定，页面显示实际人数和原因构成。
先提交重跑准备请求，携带来源视图和观察到的摘要修订供审计；后台固定成员及来源 Run。
结果筛选文案明确“按固定时点的失败结果生成重跑名单”，实际人数可能随该视图结果变化。
后台记录实际 basis revision 和固定时间，不因整批其他账号完成就要求用户重新提交。
显式选定目标严格使用原 ID 集合，不追加后来变失败的其他账号。
准备中显示“正在固定本轮范围”，不提前改当前结果归属或假定最终人数。
完成后新增同批轮次，返回本轮固定人数、接受/等待/无法执行的明确结果。
重复点击复用本次受理键，不产生两个相同轮；用户明确再次重跑是新的意图。
活动中的项目不重复创建 Run，按服务端返回显示等待或已在执行。
少量冲突不得阻断其他目标；不能要求用户逐项确认后才允许批量重跑。
远端未返回不能被 UI 统一封锁；请求仅传 `retry_mode=automatic`，由领域适配选择 manual/resume/confirm_receipt。
结果准备期间发生来源变更时以服务器真正冻结的成员为准，不在前端重算名单。
不能将 observed summary revision 当作严格 CAS，避免持续运行批次的重跑永远准备失败。
真正的准备故障通过轮次资源 failed/preparation_error 展示；可以继续恢复原意图，不要求逐账号核对。
成员冻结前被取消的轮次为 completed、`completion_reason=cancelled_before_freeze`、目标数 null，显示“准备已取消”。
该轮不切换当前归属，也不显示“目标 0 / 全部成功”；冻结完成后的取消按已有固定人数结算。
没有可选目标时显示“本轮无可执行目标”，轮次 completed、目标 0，不计成功 1。

### 6.2 其他复用动作

“对同一批账号再次执行”创建新批次，复用固定身份而非重新按条件查询。
该入口使用 batch_targets 来源，传原批全部成员、显式目标 ID 或指定视图的结果筛选；不在浏览器拉全名单再逐项拼装。
结果筛选按服务端冻结时点固定，明确显示来源视图与时点；不能把旧失败数当作新名单已固定。
服务端为新批复制固定成员并重新预检，新批拥有独立根目标和 Run，原批仍可追溯。
“复制条件新建”回到创建页，保留可编辑条件与参数，必须重新固定名单。
“重跑未成功”留在原批新轮，保留原 task 检查点及执行归属。
三个动作的说明、目标来源和回执必须区分，不能共用一个含糊的“重跑批次”。

### 6.3 取消未开始与请求停止

第一版仅提供 `cancel_not_started` 和 `request_stop`，不提供无语义定义的暂停按钮。
“未开始”以账号链首次实际执行为界，包含尚未展开/未物化的固定目标。
已开始账号链的必需子任务和续接继续收口，不能把所有 queued 子 Run 一概取消。
“请求停止”包含取消未开始账号链，并对范围内已开始的 owned 链调用现有安全检查点；不再展开新账号。
回执后显示“停止中”，待实际收口后更新结果；不强杀线程，也不停止属于其他执行的 blocker。
控制提交携带期望 control revision，旧页面的冲突返回后重新读取并解释现状。
同一控制重复提交幂等，先返回原命令，不因原 expected revision 已过期而拒绝回执恢复。
控制按钮进入等待态；失败不得把页面乐观改成已取消。
控制期间继续接收摘要，显示已完成、正在收尾、尚未开始等真实数量。
取消与新轮准备并发时由同一控制修订决定；准备请求须显示被取消或仍可继续的明确结果。
没有对应能力时隐藏该动作或显示具体原因，不通过通用按钮调用不支持的服务。

## 7. 请求、竞态与刷新约定

| 场景 | 页面行为 | 必须保持的状态 |
|---|---|---|
| 慢预览 | 显示准备时长、可离开后返回；无虚假进度 | 查询摘要、selection ID |
| 明细 GET 失败 | 保留旧页并显示更新时间，可重试 | 轮次、筛选、选中项、滚动 |
| 创建/重跑 POST 回执丢失 | 同键找回；不自动换键重建 | 幂等键、摘要、准备请求 ID |
| 401 | 登录后恢复上下文，再核验受理结果 | 草稿与明确请求身份 |
| 409 修订冲突 | 读取新状态，显示变化原因 | 用户原选择，不擅自重选 |
| 422 字段错误 | 在字段旁显示分类原因并聚焦首项 | 其他有效输入 |
| 服务暂不可用 | 保留已受理记录，提示恢复中 | 批次与历史结果 |
| 切换轮次后旧响应到达 | 丢弃旧响应 | 当前 route/request epoch |
| 摘要投影滞后 | 显示汇总同步中，不虚报终态 | 最后确认修订 |
| 后台占用变化 | 更新资格/等待原因，不改固定成员 | 原目标清单 |

同一页面同一资源只保留一个在途刷新，必要后续刷新合并，不堆积定时请求。
活动详情摘要约 2 秒，批次列表 5—10 秒，筛选选项低频或按需获取。
隐藏标签页停止轮询；返回时刷新一次；结束批次自动轮询停止。
有准备/控制/重跑请求尚未收口时，即使旧批次 ended 也继续跟踪该请求状态。
请求身份包含批次、视图、轮次、筛选和游标，变化时递增 epoch。
前端按 revision 更新变化区域，不能每次整页重绘导致焦点和文本选择丢失。
状态筛选下成员改变时固定当前浏览页，提示结果已更新；主动刷新再重置游标。
账号明细排序不随运行状态变化来回跳动，默认保持固定 ordinal。
初次加载与后台刷新使用不同反馈，后台刷新不遮挡表格或禁用所有阅读操作。
创建成功只加载当前批次摘要和明细，不串行刷新账号、总览、任务中心全部页面。

## 8. 可访问性与手机验收要求

沿用现有现代界面，不添加旧版页面或双版本 CSS 分支。
桌面验证 1,024 / 1,440 像素，手机验证 360 / 390 像素及横屏。
输入有可见标签，错误关联字段；状态不能只依赖颜色或 hover。
键盘可完成筛选、多选、预览、创建、轮次切换、明细过滤和查看执行。
长错误与条件可换行，主要按钮有效触控区域约 44 像素，不截断关键信息。
仅表格在必要时局部横向滚动，整个页面不得横向溢出。
动态状态使用适量 aria-live，数字变化不持续抢读，也不移动焦点。
详情打开/关闭、导航返回后恢复原触发点；移动端关闭侧栏后焦点可继续操作。
网络慢、后台刷新和统计变化不能覆盖用户正在编辑的筛选或取消已选项。

## 14. 迁移、发布与回退

### 14.1 兼容版本门槛

先发布能识别新管理标记、轮次关联、控制门闩和清理引用的兼容版本，再开启新批次受理。
兼容版本在新功能未启用时必须维持旧路径；缺失管理标记的历史批次继续旧汇总。
同一批次摘要只能有一个写入所有者，不能旧 `_refresh_batch` 与新投影互相覆盖。
数据库结构采用增量迁移，迁移可重复执行；新旧读路径必须能识别结果 schema 版本。
旧客户端不得绕过新管理任务的重跑轮次入口；服务器对所有人工入口统一适配。
历史无固定名单/owned Run 的批次不伪造完整统计，标历史能力限制并保留原详情。
schema 或运行时不满足最低版本时停止新受理，已受理数据保留并报告具体版本不兼容。

### 14.2 开启与发布顺序

顺序为：独立工作区/测试库验证 → 代码评审 → 提交 → 推送 → 核对远端提交 → 部署该提交。
先迁移结构及兼容服务，再开启新菜单只读，随后小批量开启新受理与展开。
先单功能小样本，再四功能和组合，再重叠批次/恢复，最后逐步迁移快捷入口。
观察指标包括受理/固定/展开/排队耗时、owner 恢复、等待原因、投影滞后、错误分类和数据库锁等待。
本地、Oracle 分别检查版本、PID/工作目录、端口、日志、healthz/readyz、真实浏览器与业务验收。
Oracle 的独立移动端等提交先合并核对，不用本地文件整体覆盖。
测试数据、凭据和日志不提交，报告只记录必要聚合与脱敏证据。

### 14.3 回退规则

新受理开关关闭后仍必须允许查询已受理批次、查看轮次和追踪结果。
先停止新增选择/批次/重跑受理，再停止展开；明确已有业务 Run 是排空还是留待兼容恢复。
回退目标必须是已具备新管理批次控制与清理保护的兼容版本，不能任意回到旧提交。
回退前确认没有旧 worker 绕过新控制继续认领，也没有两个版本同时写摘要。
保留新增表、固定目标、轮次和请求身份，不通过删除结构清空待办。
配置与 schema 版本记录可核对；重新启用时按持久游标与 fence 恢复，不从头重跑业务。
若兼容回退尚未准备好，该版本不得开启生产受理，不能把回退留作上线后的补救。
