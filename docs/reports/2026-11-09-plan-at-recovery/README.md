# 独立查套餐错误诊断与 AT 自动恢复验收

最终合并及双端发布见[部署验收](deployment.md)，全部分支核对见[合并审计清单](merge-audit.md)。

## 实现范围

- 「配置 → 注册与账号 → 查询套餐」新增 `PLAN_CHECK_AUTO_REFRESH_AT_ENABLED`，默认开启。
- 仅独立查套餐在 AT 缺失、本地过期或套餐接口返回 HTTP 401 时自动刷新一次，复用现有刷新 AT 驱动及认证策略。确认新 AT 保存后补查认证失败国家，已经成功的国家不重复查询。普通重跑入口继续可用。
- 新任务冻结开关和刷新配置；历史任务首次手动重跑补齐新增配置，原国家、套餐预算、支付预检选择保持原值。已有开关快照的重跑继续沿用快照。
- 逐国错误使用公共分类，列表与详情一致；旧记录从所属 Run 的最后逐国回执批量恢复，只补读取结果，不改历史数据库事实。HTTP 401 仅表示 AT 未通过本次验证。
- 自动刷新失败优先显示认证原因，并保留逐国错误和实际刷新阶段。没有足够证据时显示诊断记录不完整。
- 注册同步查询、注册自动补查和注册任务内套餐重跑不启用这项恢复编排。

## 持久化与任务边界

单次刷新额度在远端认证前写入原 Run；新 AT 写回校验当前执行围栏、账号邮箱和原 Token，再读回确认。同一 Run 重建恢复器不会再次刷新，手动新 Run 重新取得额度。认证复用父任务租约和并发许可，释放套餐线路后单独领取认证线路。

逐国补查只增加一次认证恢复请求额度，不清零原请求次数、库存等待或截止时间。旧 401 和过期信息保留在事件历史中，补查排队及取消时不会把旧失败证据写回新 AT。刷新已经取得完整确认回执时，后续只读套餐查询失败或取消保留其真实终态。

修复手动重跑附带发现的时间兼容问题：账号读取投影同时接受带时区和不带时区的排队/执行时间，避免刚重跑的任务被误显示为异常。

## 验证结果

全部数据库测试使用非生产 `turb_test` 和独立 `test_` schema，兼容导出关闭，外部套餐请求和认证调用使用合成回执。

- 最终套餐恢复、国家进度、任务错误、旧记录读取、读取性能、重跑及配置 UI 合集：320 项测试和 318 个子场景通过。
- 配置导航与任务日志前端：63 项通过。
- 相邻套餐、支付预检及注册套餐查询回归：85 项测试和 31 个子场景通过。
- Ruff、JavaScript 语法和 `git diff --check` 通过。
- 隔离 WebUI 真实浏览器：新增开关显示、关闭/开启保存及热加载通过；旧任务列表与详情分别显示逐国 HTTP 401/503，浏览器无错误日志。预览进程已停止，临时 schema 已清理。
- 扩展配置检查另有两个原有失败，已在未修改的主工作区复现：历史 HME 可编辑字段集合断言、协议版本帮助文案旧断言。本次未修改这些无关断言。
