# 邮箱管理与消费边界审查

## 最终职责

| 操作 | 负责方 |
| --- | --- |
| 母号、Cookie、邮箱创建、别名/子邮箱生成、同步和投递运维 | Email Butler 及 Oracle 邮箱服务 |
| 手动选择并导入已有完整地址、保存固定收件连接 | Turb；Butler 导入时交接原地址归属 |
| 本地库存统计、原子领取、任务邮箱归属、取码和账号操作 | Turb |
| 已使用邮箱服务登记 | Turb 事务写结果及持久回执队列，后台报告 Butler |

新注册仅使用五个本地池。空库存提示手动导入，不远端购买、生成或自动补号。原任务继续绑定原完整地址；未知结果不释放，不重领。邮箱失效不等同于 OpenAI 账号封禁。

## 已修复边界

- iCloud 连接并同步、远端母号目录、CloudMail Token/域名运维、MailCode 供应目录接口返回 410；配置页退出邮箱供应和生成管理，保留历史配置读取及收码连接。旧 iCloud create/sync 客户端也显式停用。
- `EMAIL_SOURCE` 仅编辑 CLI 的五个本地来源顺序；保存其他配置不会被退役的子邮箱生成校验阻塞。
- Butler HME 手动导入前先只读解析原身份，再以固定消费者和稳定 acquisition 完成永久库存交接。短读租约到期不解除归属。交接超时只重放原地址；不导入未确认库存。
- 固定 Butler HME 新领取必须已有交接证明；历史 claim 的恢复和已用邮箱的固定读取保持。直接固定 IMAP 邮箱无需 Butler 交接。
- 使用结果与回执同一 PG 事务保存。HME 回执后台重试原 operation、原连接和原凭据引用；断网不改变注册成功结果。未知结果不报告成功，晚到失败不能覆盖成功，失败不把整个上游邮箱永久停用。
- 旧普通 Butler lease 的变更仍按旧一次请求兼容，缺少幂等合同，不加入后台重放。新注册不再使用该旧租约路径。
- 历史 Remail 恢复只复用已保存凭据或查询原订单；prepared/rejected 不重新购买。
- 历史封号邮件扫描的就绪条件改为读取连接；本地新库存为零也能扫描既有账号。

## 支持的手动导入

| 来源 | 格式与限制 |
| --- | --- |
| Butler HME | 每行一个完整 `@icloud.com` 地址；母地址与 plus 子地址分开，导入时登记归属 |
| Outlook | `email----password----clientId----refreshToken` |
| 通用 API / 直接购买 | `email----code_url`，可加第三段 `expires_at`；也可填批次有效期 |

有效期必须是带时区的 ISO8601 绝对时间，例如 `2026-10-28T12:00:00+08:00`。单行第三段优先于批次值；未提供有效期保持旧格式兼容，不猜测期限。复制通用 API 素材保留有效期。

导入、统计、领取、恢复、缓存和每轮取码共用有效期规则。过期保留原占用，不自动换号。结构化响应中存在的收件人和时间必须匹配；拒绝的旧码、错误收件人或不可读候选不能再经全文正则接受。纯文本收码保持兼容，但不能提供结构化收件证明。TLS 验证已开启，日志不记录取码 URL、OTP、Token 或正文。

Butler 普通五段账号导出缺少永久归属及固定读取授权，**当前不支持直接当通用消费包导入**。非 HME 可使用明确的 Outlook 或通用 API 材料直接导入；以后 Butler 其他 provider 需实现固定身份、读取授权及有效期合同，不能伪装成 HME 转发路由。
