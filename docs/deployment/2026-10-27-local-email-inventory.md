# 本地邮箱库存与固定收码连接

用户要求以本地邮箱列表为唯一新注册库存。库存用完后由用户从 Email Butler 或其他来源手动导入，Turb 不查询远端容量、不申请新远端邮箱、不自动生成子邮箱。

## 行为

- 注册页统计五个本地池：Outlook、通用 API、域名邮箱、iCloud 隐藏邮箱、Butler 导入邮箱。计数与原子领取使用同一可用条件，已注册、结果未知、无效或非活动地址不能新领取。
- 领取在同一 PostgreSQL 事务保存稳定 acquisition、owner、完整邮箱和任务关联；重跑恢复原地址。旧远端意图和历史子地址仍保留原身份；未明确的远端意图禁止换领本地地址。
- 导入保留 Outlook 的 `email----password----clientId----refreshToken` 与通用 API 的 `email----code_url`，新增 Butler HME 每行完整 `@icloud.com` 地址。后者保存固定 Butler profile、最终转发邮箱与版本化 Key 引用，导入过程不申请租约。
- Butler 其他 provider 的普通导出缺少严格收件身份，不能仅凭邮箱单列导入成可用 Butler 库存。Outlook 四段和通用 API 两段仍可导入不同服务商邮箱；域名相同不决定取码方式。
- 跨来源已有地址、已注册账号、历史分配和未知领取均去重，重复导入不会恢复库存。Key、完整收件连接和原始邮件不出现在列表中。
- 子邮箱仍在 Oracle Butler 手动生成，iCloud 每母累计 1 个，其余类型采用各自策略；Turb 不自动同步新增库存。

## 验证和发布

开发验证使用独立 `mail_prepare_20261027` 数据库的临时 schema，不在生产库运行测试。上线前保留数据库、配置和源码备份，只在活跃任务、未知执行、有效账号及 OTP 租约和临近执行队列均为空时重启。生产验收只读，不消耗邮箱或触发真实注册。

新增 `email_pool_butler` 与 `local_email_claims` 表；旧邮箱池、历史子地址与已确认远端领取账本保留。领取永久记录完整地址，状态重置或删除展示记录不能让已发行地址再次分配。固定 profile 与领取在同一事务保存引用，之后更改全局配置不改变历史目标。

已完成独立审查并修复固定路由恢复、缓存丢失后的来源判断、OTP fence、并发状态更新及反向批次导入锁顺序；导入成功立即刷新注册来源，页面无需重新加载即可使用新增库存。

验证包含 99 项相关后端集成检查、21 项前端检查，以及后续补充的并发、固定连接和身份恢复定向回归。浏览器使用独立测试库的 85 条合成库存，确认注册页显示 85、Butler 导入弹窗可用且桌面无横向溢出。历史远端发号/自动同步断言不代表当前本地模式；旧测试中无关的任务分页与筛选失败在 `f597902` 基线也可复现，未为通过旧断言重新开启远端领号。
