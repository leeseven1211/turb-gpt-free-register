# 2026-10-27 历史 HME 母子邮箱收件验收

用户要求既有 iCloud 隐藏邮箱和子地址统一由 Email Butler 收件、完成真实验证码与性能验证，并部署适配。

## 身份与实际收件路由

历史账号继续保留 `email_source=icloud_hide`，以维持完整地址、母子关联和原 acquisition/owner；新任务使用 `email_butler`。收件来源与历史身份分离：历史母子地址的 OTP、邮件列表/正文、封号邮件扫描都使用固定 Butler 连接，不再依赖本机 iCloud 服务。

本轮额外固定 3,429 个原本依赖全局 fallback 的母资源。当前 3,601 个母资源及 192 个 allocation 全部绑定 `forward_butler`。在同一事务内逐行比较，除了新增收件 profile 引用，业务地址、归属、状态、策略其他字段及时间戳均未变。未将旧来源批量改名。

固定 profile 优先于全局设置；单个 profile 无效时仅该地址明确失败，不回退其他邮箱，也不抹去其他地址结果。统一模式下旧本机 API 禁止生成新的 HME 子地址，已持久化的旧生成请求仍能恢复。库存创建与分配继续由 Butler 统一管理。

## 真实收码与性能

仅对两个已有账号触发登录邮箱验证码；收到即停止，没有提交 OTP、完成登录、注册新账号或改动凭据。以下端到端耗时使用本机同一时钟：

| 样本 | 发码请求至 Turb 返回 | Gmail 到达至 PG 入库 |
| --- | ---: | ---: |
| 已有子地址，账号 #3827 | 16.577 秒 | 3.355 秒 |
| 已有母地址，账号 #3110 | 18.552 秒 | 5.397 秒 |

原始 MIME 严格匹配完整目标，缓存证据重新解析一致、OpenAI 来源可信；真实子地址不能被母地址或兄弟地址领取。错误最终邮箱和晚于该邮件到达的时间边界均不能返回该码。重复只读查询返回相同码和稳定消息身份，不消耗缓存。

真实母、子邮箱的邮件列表均 HTTP 200（各取前三封），列表耗时分别 9.687、11.644 秒；正文均 HTTP 200 且非空，分别 2.170、3.390 秒。跨身份正文 ID 读取均拒绝。这是整箱查看路径，不能当作 OTP 等待耗时。

两封邮件的 Oracle 本机缓存 API 查询约 5–39 毫秒。经公网每个地址各三次查询：子地址中位 1.981 秒（1.116–4.785），母地址中位 1.869 秒（1.457–4.849）。这是已有缓存的读取延迟，不是邮件送达延迟。两机时钟存在差异，不能直接将跨机绝对时间差用于分段统计。

历史 723 封邮件通过只读 IMAP 实际 INTERNALDATE 核对：Gmail 到 PG 的中位 12.386 秒，p95 26.897 秒，p99 40.314 秒。该历史样本只有一个 OTP，不能称为 OTP 延迟分布。最长 336.804 秒的异常主要发生在发现邮件前，根因尚无充分证据；本轮未盲改收件调度。
