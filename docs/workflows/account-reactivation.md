# 账号解封后恢复 AT 刷新

OpenAI 恢复访问后，本地仍会保留先前确认的停用状态。普通查活、自动刷新和批量刷新不会自动清除这个状态。

收到恢复访问通知后，在账号行的「更多」菜单选择「已解封，恢复账号」，再执行「刷新 AT」。恢复只解除本地当前停用标记；历史封禁原因、时间和邮件证据继续保留，不代表远端登录已经成功。AT 必须通过新任务重新获取，Codex 凭证必须重新授权。

有账号操作仍在执行时，恢复请求会被拒绝，等待任务结束后可再次操作。旧失败任务和日志保持原状；没有新任务入队时，页面直接显示跳过原因。

接口为 `POST /api/accounts/<id>/restore`，需要 WebUI 正常鉴权，并提供 JSON：

```json
{"reason": "已收到 OpenAI 恢复访问通知"}
```

恢复使用专用存储命令，原子更新账号及关联 Codex 凭证的生命周期状态，不修改密码、AT、TOTP 或凭证 JSON。同一封旧封号邮件不会再次覆盖显式恢复；新收到的封号通知仍会标记停用。历史任务不改写，恢复后的刷新通过现有入口创建新任务。
