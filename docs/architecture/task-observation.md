# 统一任务步骤与日志

## 目标与边界

任务中心、注册任务页和批次卡片统一使用按 Run 生成的进度快照。模板描述计划，事件描述实际发生的事情；任务终态不能替代阶段成功证据。本次整理观测与报告契约，不调整注册、邮箱租约、远端写入和重试的业务安全边界。

PostgreSQL 仍是任务、执行与事件的唯一事实来源。JSONL 是带关联字段的运行日志；旧文件和历史快照只通过兼容读取适配，不回写生产历史数据。

注册阶段转换同时保存在源任务的 `progress_steps.<stage>.transitions`，每次转换具有独立 UUID。统一投影临时失败后可从源记录重新同步全部转换；同一步先失败再重试成功的记录不会互相覆盖。普通日志只继承同一任务、Run、阶段中的事件上下文，跨任务或新事件不能沿用旧事件身份。

## 统一模型

`core/operations/stages.py` 维护阶段目录、任务模板和原始阶段到业务步骤的映射；`core/operations/progress.py` 只从完整 Run 的事件与持久化阶段证据构建快照。`flow_for()`、注册页和任务中心复用同一模板，前端不通过日志文本推断成功。

存在线路记录的注册进度快照使用 `flow_version=3`，其他任务继续使用版本 2，包含 `main_steps`、`current`、`outcome`、`failure`、`source` 和内容修订号。每个步骤包含稳定 ID、中文名称、原始阶段集合、状态、展示状态、原因、时间、事件关联、子步骤和尝试记录。事件历史保留重复执行及协议回退；新增阶段不会被静默丢弃。

步骤状态仍使用 `pending/running/success/skipped/failed`。额外展示语义包括记录不足、未执行、已中断和待确认，不将记录不足展示为已成功。历史阶段只有开始记录、但执行已进入后续步骤时，使用中性的“记录不完整”；模板中声明的依赖阶段有未恢复的失败事件、且后续步骤没有进入记录时，显示“未执行”。已观测的执行记录始终优先；不从模板索引推断并行子任务或未知节点未执行。已经进入但没有收口、或远端结果不明的步骤仍保留“未确认”或待对账。显式阶段成功只关闭该阶段；收到 Run 成功不批量涂绿，收到 Run 失败不批量涂红。后续重试或回退确认成功后，先前失败的尝试显示“已恢复”，仍保留原始失败记录。

计划顺序用于尚未执行的步骤，实际事件顺序用于已执行步骤。不同驱动、补跑、条件分支和重试可采用不同顺序，界面标明实际顺序；浏览器等跨阶段作用域保留起止记录。当前步骤取最近实际活动，不取模板中的第一个 running。事件增量游标保持 ID 语义，时间显示沿用浏览器时区。

失败定位优先使用未被后续成功恢复的显式失败事件，再使用保存的失败上下文；缺少明确失败事件时只标明最后活动及“位置待确认”。结果包含安全错误分类、原始阶段、主步骤、事件 ID、原因、下一步建议及远端待确认标识。`request_unknown/attention_required` 保持独立结果，不能当作普通失败重新执行。

## 注册线路与步骤实例

注册快照在 Run 内先选择当前 `route_attempt_no`，主卡片只展示该线路，`routes` 保留历史。卡片总体状态取 Run 结果，历史线路失败不覆盖当前运行状态。人工重跑的执行耗时保持各 Run 独立，线路内步骤按对应 `step_instance_id` 配对；重新进入阶段创建新实例，不沿用上次开始时间。

任务发起线路时固定运行和线路上下文，传给代理申请及驱动回调。同一阶段的 running/终态共享实例号，晚到的旧线路回调仅保存为原线路历史，不重置当前卡片。无法确定线路或 Run 的旧事件放入 `history_unknown`，不根据文案或相近时间猜测归属。

`time_basis` 明确当前线路步骤与整次执行耗时的区别。认证父组保留当前子步骤间必要等待的墙钟区间，不直接相加并行子阶段；历史只有秒级时间或缺少边界时，不声称具备更高精度。

## 任务覆盖

| 任务 | 主要步骤与分支 |
|---|---|
| registration / registration_resume | 网络、准备或复用邮箱、驱动、页面与认证子步骤、资料、Token、套餐/2FA/Codex；后置顺序按驱动或实际执行记录 |
| codex_retry | 预检、网络、驱动、授权地址、登录（密码/MFA/邮箱验证码）、工作区、手机验证、授权、回调、保存与确认凭证 |
| twofa_retry / account_setup_retry | 网络、套餐、按计划配置密码/2FA；协议尝试与浏览器回退分别保留 |
| password_setup / password_change | 网络、浏览器、登录验证、设置或修改密码及确认 |
| twofa_setup / twofa_change | 网络、协议 2FA；需要时进入浏览器登录或回退 |
| account_completion | 生成计划、提交刷新/账号配置/Codex 子任务；父步骤显示提交与依赖结果，子 Run 保持独立 |
| live_check / token_refresh | 预检、网络、Token 校验或登录/MFA/邮箱验证码、获取 Token |
| codex_token_refresh | 预检、刷新 Token、保存凭证 |
| plan_check | 预检、网络、查询套餐 |
| deactivation_mail | 预检、邮箱扫描；明确不支持、取消或失败 |
| extract_link | 预检、Token 校验、按需刷新、提炼与远端回执 |
| email_change | 邮箱、网络、发起换绑、按需重认证、验证码、确认及本地写回 |

批次维持并发执行，汇总当前阶段与失败阶段分布。不能把批次中的并行任务误画成一条串行执行链。

## 日志与交互

阶段事件与旁路 JSONL 共享事件 ID 或来源事件 ID、UUID、原始阶段和业务步骤关联。原生任务的公共执行入口自动接入普通 logger，通过当前任务上下文标注阶段，避免全部显示为 registration/runtime；嵌套的独立子 Run 不向父 Run 复制日志。旧日志没有可靠关联时显示“未关联日志”，不猜测阶段。列表、筛选、步骤和事件优先使用后端共享目录的中文阶段名称。

任务详情先显示结果和失败位置，随后显示实际步骤。步骤区使用固定高度的紧凑单行卡片，按宽度和步骤数量调整密度，能放下时全部展示，超出容量时使用按钮翻页，不挤压下方时间线、运行日志和诊断资源。卡片由箭头连接，保留名称、状态和耗时，运行中的步骤持续计时。鼠标悬停或键盘聚焦展示阶段时间、尝试记录与子步骤；长浮层支持滚动，键盘向下键进入浮层，Esc 关闭并恢复焦点。触屏点击卡片后，日志上方展示所选步骤的起止时间与耗时。已跳过的主步骤与子步骤不显示，原始尝试记录和日志保留。点击卡片可筛选事件与运行日志，显示筛选条件和清除入口。普通技术字段默认折叠，错误文案与时间格式统一。注册页“查看日志”进入同一任务详情；批次卡片消费相同快照。

父任务详情提供独立子任务的 Run 入口。提交成功与子任务执行成功分别表达；等待子任务造成的 `partial_success` 不生成虚假的失败摘要。部分成功但有真实失败证据时，摘要保留具体失败步骤及子任务关联。

## 扩展与验收

新增任务需注册模板及原始阶段映射，执行器显式报告 running 与终态，并使用统一 reporter/log context。新分支保留稳定步骤 ID 和尝试标识，不复制前端模板。

阶段只在其真实作用域内收口：预检包含的 Token 刷新明确失败时，预检与刷新分别记录失败；刷新已经成功后，后续本地异常不能覆盖其成功记录。批量扫描每个账号的结果使用关联账号的普通事件，主阶段在整个批次汇总后才结束，部分账号成功不代表批次成功。取消、租约丢失和远端结果未知使用中断或待核验事件，不能伪造成功或失败。已确认的业务写回保持成功，资源服务收口告警单独记录为警告事件。

例如一个新业务步骤可以注册为 `_step("provider_check", "检查服务状态", "account", "provider_request", "provider_response")`；执行器对每个原始阶段明确报告开始、成功、跳过或失败。执行器只有确认跳过时才能上报 `skipped`。展示投影可提前依据本次注册 Run 保存的 `config_snapshot` 将明确关闭的 Codex、2FA、套餐查询分支标为跳过；已有执行事件优先，缺少配置的历史任务不推测跳过。结果节点在自己的收尾事件到来或 Run 终结前保持未开始，整体运行状态仍通过 `outcome` 单独保留。未登记阶段仍会保留为动态节点，便于发现模板遗漏；后续应补入共享目录。模板 API 返回独立副本，调用方不能修改全局定义。

回归覆盖全部任务模板、真实驱动顺序、未知阶段、重试恢复、步骤日志关联、缺失证据、未执行步骤、部分成功、取消、中断、远端待确认、历史时间和增量游标。存储测试在独立工作区及非生产数据库的一次性 schema 中运行；页面用真实浏览器验证桌面与窄屏，不触发真实注册或远端账号操作。
