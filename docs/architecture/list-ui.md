# 列表统一交互规范

任务中心是此规范的首个实现；第五阶段全部批准页面均已完成迁移并按场景接入公共列表能力，包括Codex、账号、批次、邮箱／代理、总览、注册Live、提链工作台及独立统计。页面只提供字段、数据和业务动作，复用 `frontend/src/components/`；非列表页面不机械增加筛选或分页。原页面迁移验收见[第五阶段完成报告](phase5-completion.md)，本轮补齐规范的UI增量、真实预览及最终前端完整检查见[开发与测试收口表](development-test-closeout-20261118.md)，生产验收继续单独记录。

## 信息密度

- 列表结构为工具栏、数据、分页，使用全站标题，不重复占用一条标题说明区。
- 单元格默认最多两行。主次字段各一行，单一长文本最多两行；省略文本保留完整标题提示，手机和键盘用户可通过详情入口读取。
- 桌面单元格垂直居中，上下使用相同内边距；单行 ID、类型、状态与两行内容在同一行内居中。不用空白占位把单行强行补成两行，主动展开的详情仍按自然高度显示。
- 结果 / 错误的默认可见文案合计不超过 10 个 Unicode 字符。使用语义分类短语，不能截取原始错误前 10 个字，也不直接展示原始 JSON。
- 错误码、具体原因、各国套餐证据、历史快照与长结果放在展开内容和任务详情中。主动展开不受两行限制，不裁切整个单元格。
- 提链成功但支付失败、授权成功但同步失败等复合结果保留两个事实；缺回执显示待确认，不能等同失败或成功；401 不代表账号停用。
- 相邻状态列只省略重复语义，不覆盖业务原值。执行状态与目标成果分别保留；重跑中的旧失败、已确认账号或凭证仍有独立意义。等待子任务不能归为“尚未开始”。原始状态通过标题提示保留，筛选按后端精确值提交。

## 筛选与分页

- 筛选入口合并到对应列名；打开浮层编辑，已筛选表头高亮，条件可清除。手机提供一个紧凑筛选入口，共用字段定义。
- 已应用条件放在任务数量同一栏，使用共享 `ListFilterSummary`。多条件横向滚动，保留完整标题和逐项清除；手机让工具按钮换行，条件与数量仍同栏。
- 使用 Reka UI Popover 的定位、Portal、Escape 和焦点处理，不另写定位引擎。
- 精确 total 的页码列表显示当前范围、总数、每页条数、邻近页码、首页末页数字入口、前后页和跳页输入。Enter 与跳转按钮等效；真实游标列表保留已有 cursor/has_more 契约，不从已读条数伪造总页数或数字跳页。
- 宽屏页码、前后页与跳页相对整个页尾居中；当前范围、总数及每页条数放最右。容器变窄时导航与统计分行，导航仍居中，统计保持右对齐。
- 页码越界归到首尾，非法输入给出就地反馈；空列表禁止翻页，加载期间禁用导航。更改筛选或每页数量回第一页。
- 手机隐藏密集页码，保留当前页 / 总页数、前后页与跳页；分页不增加页面横向溢出。

## 组件与职责

| 实现 | 可复用职责 | 页面提供 |
| --- | --- | --- |
| `ListCell.vue` | 两行排版、省略、完整 title、主次文字与语气 | `text`、`secondary`、`title`、`tone`，可选主行 slot |
| `ListResult.vue` | 短摘要、原生可聚焦展开入口、完整明细 | `label`、`secondary`、`title`、`tone`、`details` slot |
| `ListPagination.vue` | 范围、每页数、页码、跳页与边界 | `page`、`size`、`total`、`busy`；双向 page/size |
| `FilterPopover.vue` | 列名筛选入口和浮层交互 | 标题、激活态、摘要、open 与编辑器 slot |
| `ListFilterSummary.vue` | 同栏条件标签、横向滚动、完整提示与逐项移除 | `items` 的 key、label、title、removeLabel；`remove` 事件 |
| `shared/time.ts` | 本地时区日期与时间的共享格式化，复用 Intl formatter | 时间值；不改变业务时间字段 |
| `shared/useColumnWidths.ts` | 拖动与键盘调整、旧列宽格式兼容、持久化与恢复默认 | 页面存储键、默认列宽、最小/最大宽度；不访问业务数据 |
| `tasks/resultSummary.ts` | 任务结果事实到短语的纯展示投影 | 任务记录与统一错误短语 |
| `tasks/statusDisplay.ts` | 列表状态收敛、重复目标标签省略与原始说明 | 执行 / 目标状态、等待及调试证据；不改变筛选值 |
| `shared/errorLabels.ts` | 消费生成目录，将结构化错误码映射为短语 | 既有 ErrorInfo 结构；不匹配原始报错文本 |

公共组件不调用业务 API、不访问页面的状态、不导入 `features/tasks` 或 `features/codex`。业务分类归领域展示模块；翻页数据请求、取消旧请求、筛选和选择状态归具体列表。共享组件使用全站 `--ui-*` 语义变量，样式随组件加载。

页面与 document 可见性分别传递，隐藏立即取消读取、使迟到响应失效并暂停轮询；返回只按最终条件恢复。已发出的写入继续保留原请求身份和回执，不因刷新失败、切页或重新挂载自动重放。详情打开时冻结公开证据，轮询不覆盖正在查看的记录；离开所属页面关闭详情和筛选浮层。

原生 dialog 的背景滚动锁按实际持有者管理：多个原生弹窗及旧全局弹窗交错关闭时，仍有持有者就继续锁定，最后释放恢复原 inline style 和滚动位置；离开页面或 document 隐藏时不把焦点拉回隐藏入口。mounted 测试验证状态与关闭顺序，真实滚轮、焦点和窄屏布局另由浏览器验收。

Codex 的 `plan`、`status`、`oauth_status` 筛选按后端精确单值提交；任务中心状态筛选也保留单值语义，不因共用组件而套用账号多值 CSV。Codex 跨页选择以 `filename` 为唯一身份，邮箱文本只用于展示和查询，不替代凭证身份。

错误目录的唯一维护入口见[错误短语分类](task-error-catalog.md)。增加任务或错误时同时登记短摘要；既有测试检查覆盖与 10 字上限，生成目录与源码的漂移在构建中发现。

任务详情复用 `TaskFailure` 合并执行与步骤的同因错误，原文与不同具体原因继续保留。阶段条、步骤证据和依赖说明共享 `flowPresentation` / `StepRelations`；它们消费[阶段关系契约](task-progress-structure-audit.md)，不推断执行顺序或重试策略。
