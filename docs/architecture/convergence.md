## 1. 目标与边界

批量命令使用统一的 Task/Run dispatcher 和执行许可。Web 进程只完成命令元数据注册并持久化请求，Worker 进程显式注册领域 handler。命令分块把业务写入和逐项回执放在同一事务，分页查询从 PostgreSQL 读取完整回执并对 command、task、run 与已知目标 ID 输出字符串。Worker 重启时，恢复流程先收口失联 Run，再仅为未取消且无有效租约的批量命令创建一次新的 Run，已提交分块由 command 级回执跳过。

目标是让一个业务规则有一个拥有者、一个页面有独立状态、接口变化能在构建时发现，并按用户操作测量性能。采用同仓库的模块化单体，前端独立构建、后端保留 Flask 与 PostgreSQL，静态资源和 API 同域发布。

本轮实现任务中心完整纵向样板：页面、API 类型、只读应用查询服务、关键行为验证及现有页面入口兼容。保留现有动作接口、权限、重跑资格和执行语义。注册驱动、重试策略、共享调度行为与数据库结构不在本轮改动范围。

样板完成后，后端第一批收口账号执行配置和旧任务查询响应，第二批按第 8 节将账号 setup / completion 执行与父子续接归入账号模块。第三阶段已完成任务写动作、恢复和统计投影收口，第四阶段已按确认门槛完成本地验收。第五阶段原批准页面迁移的本地实现与验收已完成：Codex、账号、批量、配置、邮箱、代理、总览、注册、提链工作台和独立统计；本轮补齐游标页尾及批量详情筛选规范的增量也已通过真实预览和最终CSS后的完整前端检查。原范围、测试组合及限制见[第五阶段完成报告](phase5-completion.md)及第13节，本轮增量见[开发与测试收口表](development-test-closeout-20261118.md)。索引、Codex精确统计合并和有边界的账号深页分页均已有正式规模证据，新增50万SQL结果见第15节；列表仍有多秒尾延迟。下方历史数字保留其测量时点；生产容量与第六阶段不因页面迁移完成而视为通过。

第六阶段已实现显式 combined/web/worker、执行 owner、持久受理、配置观察、真实停止和就绪状态，以及固定版本 Waitress、角色控制、服务模板和显式总停止预算。固定包切换/回退与一次完整五阶段本地联合回归已分别通过限定独审，见[发布兼容性结果](phase6-release-compatibility-results.md)与[Codex兼容及联合回归结果](phase6-codex-return-compatibility-results.md)。30万/50万读取、混载与故障专项保留各自测量条件；完整容量/故障范围继续按项管理，本次defer四格已独审收口，K05残余资源恢复边界仍未关闭，生产切换尚未执行，不将单项通过升级为阶段整体完成。第10、11节保留当时停止边界，后续获批批次见第12节及顶部当前收口记录，不据此扩展新页面或新流程范围。

## 2. 模块所有权

| 模块 | 拥有的规则 | 公开接缝 | 后续收敛方向 |
| --- | --- | --- | --- |
| 注册 | 注册身份、驱动、步骤、续跑与邮箱回收 | registration service / dispatcher | 每驱动独立方案与验收，不通过公共改造改变行为 |
| 账号 | 查活、套餐、密码、2FA、换绑及账号事实 | accounts 应用服务 | WebUI 中的非注册 handler 下沉到领域协调器 |
| Codex | OAuth、凭证确认、刷新和补跑 | codex 应用服务与驱动 | 收敛入口与结果契约，复用任务执行底座 |
| 邮箱 | 来源、库存、租约、取码、服务事实 | email 服务与提供方 Adapter | UI 不判断租约归还条件 |
| 提链 | 平台订单、提链与支付结果 | extract_link service / provider client | 保持平台回执与本地状态的区别 |
| 批量任务 | 固定范围、批次、轮次、归属与报告 | bulk_operations service | 复用现有任务，不增加第二套执行器 |
| 任务中心 | Task/Run 查询、公开状态与错误展示 | operations query_service / HTTP 契约 | 读、写、运行恢复和投影逐块分离 |
| 运行基础设施 | 执行许可、租约、心跳、恢复 | operations/runtime 接口 | 依据负载测量分离 API 与 Worker 生命周期 |
| 存储 | PostgreSQL 事务与查询 | storage 领域仓储 | SQL、锁顺序与约束归仓储，业务编排归服务 |
| 前端 | 页面状态、交互、组件、展示 | 显式 API 客户端与页面桥接 | 每迁移一个页面替换一个入口，停止旧实现增长 |

依赖方向为 `HTTP / CLI → 应用服务 → 领域能力 / 仓储 → 外部客户端 / PostgreSQL`。前端只通过 HTTP 访问业务。`core` 不导入 `webui` 或 CLI；仓储不发远端请求；注册驱动不调用其他驱动的私有实现。

采用已有的 Service、Repository、Adapter/Strategy 和持久 Task/Run 模型。不新增通用工作流引擎、微服务、Redis 或 Celery。需要新组件时先证明已有组件无法解决的具体问题。

## 4. API 与展示契约

[任务 API 定义](../../contracts/task-center.openapi.json)与[Codex API 定义](../../contracts/codex.openapi.json)分别作为已迁移页面的类型源；现有 URL、字段和各领域响应 envelope 保持兼容。Codex 的 `plan`、`status`、`oauth_status` 按精确单值提交，跨页选择以 `filename` 为身份，不套用账号多值 CSV 约定。下面任务查询、游标与进度条款仍只描述任务领域，契约不承诺全仓库已统一。

- 路由解析 HTTP 参数，查询服务调用仓储并执行公开展示投影。
- 列表使用轻量结果及 revision；不附带 batches，facets 只在查询变化、手动刷新或 30 秒缓存到期时更新。
- 详情显式请求 `include_events=0`，再按选定 Run 拉完整 progress 与分页事件、日志。
- 公开失败状态与内部事实分别保留；重跑能力仍按内部事实由原逻辑判定。
- 事件 `after_id` 与日志字节 `cursor` 语义不同。省略表示最近记录，显式零表示从头读取，不能把最近页的 `has_more` 当成向后游标。
- 人工重跑是新的意图；网络重试保留同一幂等键。前端不增加逐账号人工核对门槛。
- 前端类型来源于 OpenAPI；API 调用只在客户端层，组件不拼接业务请求，不反向依赖其他页面的全局函数。
- 进度增加独立的阶段展示契约：条件、依赖状态、子任务引用、重试证据和显式并行组。`observed_order` 是首次记录顺序，不代表严格串行；原状态、事件和运行语义保留。18 类模板核对与覆盖缺口见[阶段审计](task-progress-structure-audit.md)。

## 5. 视觉与交互决定

后续列表统一遵循[列表交互规范](list-ui.md)：列名筛选、默认两行、结果摘要合计不超过 10 字、按真实分页契约复用导航。任务中心、Codex、账号、批量任务及本批邮箱/代理已接入公共组件与列宽能力，禁止逐页复制相同布局和交互。

延续现有控制台：浅灰背景 `#f4f6f9`、白色表面 `#ffffff`、正文 `#172033`、次级正文 `#596274`、紫色主操作 `#5b5ce2`、红色失败 `#db4b55`。使用已有 `--ui-*` 语义变量和中文系统字体，时间/ID 仅在需要对齐时采用等宽字体。

任务中心以排障为主，列表直接衔接全站顶部导航，布局采用“任务工具栏 → 数据表 → 分页”，不重复展示页面标题、说明或刷新区。筛选收进对应列标题，点击列名或图标打开浮层；已应用条件高亮表头并显示可清除的条件标签，不保留独立筛选表单。11 个字段映射到 10 个可筛选列，创建时间起止共用日期浮层。行内保留类型、目标、状态、步骤和原因，选择后显示批量动作，详情使用独立对话框组织 Run、进度和三类证据。

筛选浮层由共享 `FilterPopover` 封装 [Reka UI Popover](https://reka-ui.com/docs/components/popover)，使用 Portal 避免被表格滚动区裁切，由组件处理定位避让、键盘关闭与焦点。保留现有表格与列宽能力；Element Plus / PrimeVue 的整表筛选无需在此引入。后续页面可复用浮层和字段定义，不复用旧页面 DOM 操作。

筛选变化重置页码；保留不在本次 facets 中的已选值。加载失败显示原因与重试，并保留已读数据。轮询不抢焦点、不重置滚动，页面不可见时停止。状态同时显示文字，窄屏列表转为卡片并局部滚动，工具栏提供一个紧凑的“筛选”入口并复用相同字段编辑器；窄屏和矮窗口允许模块整体滚动，保证分页和详情底部可达。对话框可键盘操作、Escape 关闭并恢复焦点，尊重减少动态效果偏好。

### 已确认的状态与详情收敛

- 列表执行状态收敛为排队、进行中、已完成、部分完成、失败、已停止和已暂停等常用显示；等待对象、停止请求与收尾保留次级说明。目标状态只隐藏重复语义，已确认成果与重跑期间的旧失败保留。详情与精确筛选仍使用原状态值，状态筛选不支持多值 CSV。
- 桌面详情标题、目标、运行状态和 Run 选择器合并一行；手机按可用宽度换行。相同失败原因只显示一个摘要，不同具体原因并列保留，原文及结构化证据可展开。
- 阶段采用紧凑横向条，取消固定步骤编号，关系说明默认折叠。明确区分未满足条件、等待子任务、受阻、重试恢复；只显示有证据的并行分组。多国查询的多个实例不能自动视为重试。
- 事件时间线、运行日志、诊断资源标签与读取控制共用工具栏，将可用高度留给证据正文。

后续列表收尾按用户原有反馈落实：条件标签并入任务数量栏，多条件使用共享横向标签组件；桌面单元格垂直居中并统一对称留白；共享分页将导航与跳页居中，统计及每页条数放右侧。窄容器分行，保留键盘操作和现有筛选、分页语义。

### 重构同步审查交互与操作流程

每迁移一个模块，同时核对原有 UI 与用户完成任务的步骤。主动指出不合理之处，给出“具体场景 → 使用影响 → 建议方案 → 影响范围”；现有界面和新样板都接受同一审查。发现的问题集中记录在所属模块设计中，不另建一份零散计划。

新发现的改造建议先与用户讨论，得到认可后才能纳入实施计划。提出建议不代表已获授权；不得自行确定优先级、排期或开始实施。用户此前已明确授权的具体改动按既有授权执行。

- 信息层级：用户能否先看懂结果、失败位置和下一步；是否重复展示状态、标题和原始技术字段。
- 操作路径：入口是否容易找到，是否存在重复填写、重复确认、跨页往返或不必要的前置步骤；复用已有边界校验，避免为同一动作增加第二道校验。
- 步骤与状态：主步骤、子步骤和重试轮次是否区分；执行中、等待资源、未执行、跳过、失败与缺少证据不能混为一谈。
- 异常恢复：能否从失败位置找到相关证据与已有恢复动作；父子任务、历史运行之间切换后能否返回原上下文。
- 一致性与复用：同类筛选、分页、详情和动作在不同模块使用相同交互；公共组件不包含特定业务规则。

展示和导航优化在已授权重构范围内推进并说明。用户完成操作的步骤与后台真实执行步骤分别审查；涉及任务顺序、重试、幂等或远端副作用的改变需明确行为差异及验收依据。注册驱动主流程继续遵循本文既有专项边界，不能以 UI 优化名义调整。
