# 代理原租约结束后的任务资源对账

2026-11-18，用户已同意本批简化方案。任务正常结束仍归还自己领取的代理；代理池继续负责现有空闲和到期回收。本批补齐进程异常退出后，原代理租约与任务资源账之间的关联。

## 实施范围

1. 领取时从原 live handle 冻结 child ID、pool resource/anchor、原始领取与到期时间及所属执行代。关联只含标识，不含代理地址或凭据，同时写入资源与对应收尾义务。
2. 只有明确使用进程内协议客户端的路径声明 `owner_process`。浏览器、可能转入 Roxy 的刷新及未知路径保守保留；不能把后台退出视为独立浏览器退出。
3. 已确认原进程退出后，核验原 child 已归还（包括现有冷却状态）或达到原到期时间，只结束对应 operation resource，随后沿用原收尾及并发名额释放。
4. 覆盖同代终态回执与原孤儿恢复 disposition；历史缺关联、错代、缺失 child、外部 actor、defer 后执行代改变保持待核验。

不新增供应商调用，不修改 child、池库存、anchor、TTL、冷却和共享规则，不重放业务，不改变远端未知结果。现有重复资源义务分别核验同一资源，不扩展为历史义务迁移。

## 并行分工与验收

关联生成、调用侧生命周期声明、存储对账、定向回归与独立审查分别推进；数据库与真实进程故障测试由主代理串行运行，避免相互影响。

先保留能复现缺口的失败，再验证原生 PostgreSQL 的精确身份、自然到期、已归还、活跃 owner、外部 actor、旧数据、共享新代不变、事务失败与确认丢失；实际进程故障与模拟 owner 的 SQL 定向结果分别记录。通过受影响的账号、Codex、代理池及任务收尾回归后更新当前报告。

本计划不包含提交、推送或部署，也不关闭用户已延期的 Oracle 隔离和大规模 SQL 优化。
