# 任务结果与错误短语目录

任务列表只显示分类短语，整个“结果 / 错误”单元格的默认可见文字最多 10 个 Unicode 字符。短语由含义概括得出，不截取错误原文前 10 字；错误码、原始原因、国家、账号和技术细节放在悬停说明或展开详情中。任务状态、恢复资格、远端回执和原始记录继续使用原有事实。

## 单一来源

- 人工维护的短语与结构化规则：[`core/operations/error_labels.py`](../../core/operations/error_labels.py)。
- 前端生成目录：[`frontend/src/generated/task-error-labels.json`](../../frontend/src/generated/task-error-labels.json)。
- 原有错误分类器：[`core/operations/errors.py`](../../core/operations/errors.py)，本次不更改其诊断规则。
- 覆盖测试：[`tests/operations/test_task_error_labels.py`](../../tests/operations/test_task_error_labels.py)。

已逐项整理现有错误分类器、套餐错误分类器和浏览器刷新错误目录中登记的 **500 个静态码**。目录还覆盖注册、认证、取码、授权回调等动态网络原因、HTTP 状态和回执缺失码。此覆盖范围来自代码登记项，不代表重新扫描了线上历史任务或修正了原始记录。

## 分类口径

| 范围 | 列表短语示例 | 保留在完整说明中的细项 |
| --- | --- | --- |
| 配置与部署 | 配置缺失、浏览器未配置 | 缺少字段、部署能力、原错误码 |
| 账号与目标 | 账号已停用、目标不可用 | 账号证据、目标与邮箱身份 |
| 并发与队列 | 等待全局空位、账号正被占用 | 占用数、上限、调度等待原因 |
| 本地执行与存储 | 数据存储异常、执行进程中断 | 异常类型、写回状态、执行归属 |
| 浏览器与页面 | 浏览器登录页未就绪、页面未推进 | 页面阶段、导航与预检证据 |
| 邮箱资源与租约 | 邮箱库存不足、邮箱租约已到期 | 服务、租约与收件路由 |
| 邮箱验证码 | 验证码等待超时、邮箱验证码被拒 | 发码、收件、提交的不同响应 |
| 密码与密码恢复 | 账号密码被拒、候选密码未确认 | 候选检查点、已提交事实、恢复约束 |
| 双重验证 | 双重验证被拒、双重验证密钥缺失 | 挑战类型、验证与激活证据 |
| 网络与代理 | 代理隧道连接失败、回调请求超时 | 发生请求、HTTP/传输码、重试证据 |
| 套餐查询 | 套餐请求受限流、多类套餐查询失败 | 各国结果、历史快照、优惠与支付方式 |
| 提链与支付 | 优惠未生效、支付确认被拒 | 提链是否已成功、支付回执、套餐确认 |
| 凭据同步与导入 | 凭据导入被拒、远端已更新写回失败 | 目标集成、远端更新与本地写回差异 |
| 未确认与诊断缺失 | 请求结果未确认、执行回执缺失 | 已知阶段、缺失证据，不能推断远端失败 |
| 未登记原因 | 原因未分类 | 完整原因与任务详情，供后续补充映射 |

500 个静态码的逐项短语可直接在 `causeCodeLabels` 和 `codeLabels` 中按原码查找；`displayCodeLabels` 保留仅由细分显示码表达的原因。

## 查找优先级与边界

1. `cause_display_code`：某些既有记录的 `cause_code` 仍是 `email_otp_failed`，细因只在显示码中。比如 `MAIL-BUTLER-V2-EXPIRED` 必须显示“邮箱租约已到期”。
2. `cause_code`：具体原因，例如验证码被拒、代理连接失败。
3. `code`、`error_code`：已有稳定主分类与兼容原因码。
4. `display_code`：缺少原因码时使用已登记显示码。
5. `category`、`source`：已有大类短语。仍无命中则显示“原因未分类”。

每一步先查固定映射，再使用适用于该字段的结构化码规则。前端不匹配 `summary`、`raw` 或 `error_message`，避免再次诊断或把包含敏感数据的原文放到列表。

以下区别必须保留：

- HTTP 401 表示当前请求未通过授权，不等同于账号停用。
- 超时、缺回执和 `request_unknown` 表示结果未确认，不等同于远端拒绝。
- 本地写回失败不抹去已经确认的远端更新。
- 支付成功与套餐确认分别展示；提链成功后的支付失败不能被改成“提链失败”。

## 扩展与检查

新增固定错误码时同时登记短语。覆盖测试会直接读取原分类器的字典和枚举，防止只靠未知兜底掩盖漏项。增加动态规则时只匹配已分类的结构化码，并保持 Python `re` 与 JavaScript `RegExp` 语法兼容。

```sh
python3 tools/maintenance/generate_task_error_labels.py
python3 tools/maintenance/generate_task_error_labels.py --check
python3 -m unittest tests.operations.test_task_error_labels
```

生成脚本只使用 Python 标准库，不加载执行器、不连接数据库。前端和后续列表复用生成目录与共享摘要组件，不复制错误原文匹配规则。
