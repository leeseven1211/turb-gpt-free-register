# 提链接口与工作台排障修复计划

> **执行方式：** 使用 systematic-debugging、test-driven-development 和并行子代理逐项执行，验证后合入 main。

**目标：** 修复实际接口字段丢失、轮询无日志与超时边界、工作台全量查询和展开后停止刷新的问题。

**依据：** [现有工作台设计](../specs/2026-10-22-extract-workbench-design.md)、[流光文档](https://int31.space/public/checkout-api)、[幻光文档](https://chongyun-link.xiaoliai.shop/static/api-docs.html)。

**现场：** #255486 在北京时间 09:18:54 获得创建回执；平台记录 09:20:03 已失败，步骤 CONFIRM、66%、SETUP_INTENT_FAILED/CLIENT_ERROR。本地没有中间事件，09:34 进程恢复才通过状态同步取得失败结果。旧进程已经退出，无法据此确定具体阻塞调用。当前列表/详情 API 单次读耗时约 11–68ms，不能把全量查询风险说成已测得的 17 分钟根因。

## 约束与审查重点

- 保留既有功能和脏文件，不打印凭据、账号、支付材料；不触发支付或消耗 CDK 的重跑。
- PostgreSQL 为事实来源；存储改动在独立工作区和测试 schema 验证。
- 提链、支付、本地权益核验分别记录；平台失败必须显示真实安全错误码。
- 监控等待到期不等于远端失败；保留远端任务编号和后续同步/重跑能力。
- 详情展开、终态、未知结果、网络错误恢复、旧数据缺字段均需验证。
