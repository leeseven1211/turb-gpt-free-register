# 全项目目录归位实施计划

> 执行方式：使用 `superpowers:subagent-driven-development`，按文件所有权分工，公共改写由协调者串行执行。

**目标：** 将已批准的业务与具体实现目录设计落地，保持业务执行行为。

**架构：** 整文件移动，显式更新静态/动态导入；保留同名包与必要兼容入口、共享状态、配置机制、资源绝对位置和前端加载顺序。

**技术栈：** Python 3.10+、Flask、PostgreSQL、普通 JavaScript、pytest、Node.js。

**设计：** [全局目录设计](../specs/2026-10-30-global-code-layout-design.md)；[逐文件清单](../specs/2026-10-30-global-code-layout-map.json)。实施基线为 `7f55e6c`，清单已登记最新 708 项。

## 全局约束

- 不执行 `rm -r` 或 `rm -rf`；文件逐个移动或删除。
- 不改函数签名、参数、分支、请求顺序、超时重试、取消恢复、状态流转及持久数据位置。
- 不复制实现；锁、缓存、线程池、ContextVar 与模块实例只存在一份。
- 三份已启用 upstream 接缝只允许设计列出的 import 路径变化，其他源码资源原样保留。
- 原 main 的两份用户修改不纳入提交；合并前映射到新路径并保留原字节内容的等价修改。
- 所有 Python 测试使用统一隔离入口、非生产数据库及 `test_` schema；测试期不触发真实业务。
- 不推送远端；完成审查与测试后合回本地 main，按已有托管方式重启并检查 readiness。
