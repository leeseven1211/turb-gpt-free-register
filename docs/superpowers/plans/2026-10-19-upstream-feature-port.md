# 公开仓库功能移植方案

## 范围与基准

以公开上游 `9a0c55b`（2026-10-18）为功能参考，本地基于 `32efe892`，移植近期能适配当前架构的能力，不直接合并上游 SQLite、旧版界面或独立浏览器驱动。

## 实现分工

1. 一键巡检：复用账号操作调度和 PostgreSQL，固定归档范围的账号清单，按需刷新失效 AT 后查询套餐；保存历史、失败详情和跳过已废结果，启动时恢复中断任务。现代账号页增加明确范围的巡检和删除已废入口。
2. 邮箱供应商：接入 MailCode、Xigua 的配置、领取、取码、换绑与来源恢复；订单身份和取码游标保存在 PostgreSQL，同一任务恢复原邮箱与原订单，不将文件缓存作为事实来源。
3. 浏览器代理：保留现有代理库存和租约，在已领取线路外包装本地中继，补充目标流量归因、后台下载拦截、握手阶段有限重连，以及可选资源明细和 JS 覆盖率。
4. 相邻改进：移植 2FA 邮箱 OTP 临时 403/429 分类重试及冷却响应；把适合转发 IMAP 的 UID/批量读取优化整合到现有实现；检查 50% 优惠筛选是否已等价支持。

## 适配约束

- 使用隔离工作区和独立测试库的临时 schema；不修改生产配置、账号或执行真实注册、购买、换绑和批量巡检。
- 保留现有统一账号操作并发预算、代理库存、执行 fence、任务取消与恢复；界面沿用当前现代版本。
- 新配置同步 schema、配置模块、模板、配置界面和 README。默认不启用额外诊断采集。
- 用户已有未提交修改与私有运行文件保持原样。通过选择性提交合入 main，不推送远端。

## 验证与交付

先执行各模块最小回归，再执行相邻与存储/运行时回归及必要全量隔离测试；真实浏览器验证新增控件、范围、状态和响应式布局，但不发起真实账号业务。合入 main 后按 launchd 管理方式重启服务，核对 PID、工作目录、端口、新日志和健康/就绪接口。

## 移植结果

| 上游能力 | 本地适配 |
| --- | --- |
| 一键巡检、历史与失败明细、删除已废 | 复用 PostgreSQL 统一父子任务、账号并发预算与执行 fence；历史固定原始 Run，重跑和取消使用当前 Run |
| MailCode、Xigua 邮箱 | 注册、换绑、CLI 与配置页共用供应商适配；原订单身份、幂等请求、游标及候选验证码可恢复 |
| 代理中继与流量归因 | 包装已领取线路，分开页面观测量和代理传输量；握手阶段有限重试，可选资源与 JS 诊断 |
| 2FA 邮箱 OTP 临时限流处理 | 同一会话内对可确认的临时 403/429 有限重试，识别业务拒绝、挑战与冷却时间 |
| 转发 IMAP 读取优化 | 优先 UID，封号邮件批量读取；OTP 保留逐封提前返回与阶段预算 |
| 50% 优惠筛选 | 本地已具备“半价优惠”语义，保留现有实现 |

隔离全量验证通过 3,247 项测试及 2,340 项子测试。同步主分支新增的 711Proxy 后，交叉回归通过 132 项后端与 173 项前端测试；后续恢复边界修复另有专项与邻接回归。真实 Chrome 已验证模拟巡检、失败明细、时间显示、弹窗焦点与手机尺寸布局。供应商购买及真实账号批处理未作为本次验收操作。
