# 邮箱失效实现计划

目标：实现独立邮箱失效标记、账号列表管理、新领取和新派生限制，并完成已确认副号范围的数据标记。

依据：[已确认设计](../specs/2026-10-25-email-invalid-design.md)。

## 约束

- 保留用户主工作区及私有数据；不使用递归删除。
- 仅通过生产服务 API 更新业务状态，不用开发脚本绕过生产数据库保护。
- 不混同 OpenAI 封号、不阻断原任务手动重跑，不把已分配地址设为退役。
- 账号、账本及母邮箱事实原子更新；新增注释、日志、文案使用中文。

## 实施顺序

1. 存储任务：独立布尔与元数据、按当前邮箱的原子批量命令、换绑与新账号写回保护、新领取过滤；TDD 验证。
2. 页面任务：列表与轮询投影、独立筛选、邮箱徽标、单号/批量标记和清除、严格 API 输入及脱敏响应；TDD 验证。
3. 派生任务：新地址分配和容量预览排除失效母邮箱，同一领取身份与旧地址恢复保持可用；TDD 验证。
4. 集成：相关隔离存储/API/Node 回归、静态检查、独立评审，整合到 `main` 并提交。
5. 上线：按原 launchd 重启，核对进程、目录、端口、日志、健康与就绪状态；只通过 API 给原副号4全部当前关联账号打标。
6. 真实页面：验证标记、筛选、显示及未改变 OpenAI 状态，核对正式库操作计数和对照账号。

## 当前证据

隔离工作区初始基线：3 个相关文件，38 项测试和 10 个子用例通过。
