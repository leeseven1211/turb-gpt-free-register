# P0/P1 性能优化实施计划

用户已在分析报告后授权处理 P0 和 P1。使用并行子 agent 开发、独立审查和隔离数据库验证。

**目标：** 消除代理全局维护争用，减少批量提交数据库往返，降低展示查询频率与响应体积。

**设计依据：** [性能分析](../../analysis/2026-10-29-performance-analysis.md)。保持现有任务模型；本轮不增加异步批次提交状态机，不处理 P2/P3，不修改注册主流程。

**技术：** Python、PostgreSQL、Flask、现代 WebUI JavaScript。

## 全局约束

- 存储修改在独立 worktree，测试仅 `turb_test` 的 `test_` schema；使用 `tools/test_isolated.py`。
- 中文文案/注释；不执行递归删除，不复制业务数据，不改 `.env`。
- 保持注册请求、导航、领取、重试、超时、状态流转；代理维护改动只缩短重复工作与锁等待。
- 容量预留、租约所有权、fence、终态写回、重跑及幂等保持现有语义。
- 已有 main 修改不纳入提交。独立验证后集成到 main、提交并重启既有服务；推送另行报告。
