# C2A 异常巡检与 AT 自动修复实施计划

**目标：** 对 C2A 已有的过期、失效 AT 和凭据异常账号，复用 Turb 现有 AT 刷新任务，保存成功后回传原 C2A 管理 ID；失败按冷却重试，服务重启后接续。

**授权范围：** 用户明确要求实现与 Sub2API 类似的 C2A 异常巡检修复功能。仅编排现有账号认证刷新入口，不修改注册驱动或认证驱动内部行为。生产配置启用、部署和真实批量修复另行报告。

## 行为设计

- 读取 C2A `/api/accounts` 的全部分页，使用 `access_token_status`、`access_token_expires_at`、`backend_status`、`status_category`、`status_reason_code` 判断；覆盖 AT 已过期但尚未进入后端错误状态的账号。
- 只处理 C2A 已有且可匹配本地的账号，固定后端摘要、原管理 ID 和邮箱；不借巡检创建远端账号。人为禁用、明确停用、资料缺失等分别记录固定原因。
- 本地已有更新且有效的 AT 时先补传；本地 AT 过期或与远端拒绝的 AT 相同时，通过现有批量任务平台提交刷新，沿用现有驱动、代理、OTP、并发和任务中心。本地 AT 缺失按现有刷新契约分类跳过，不借巡检改变认证准入规则。
- 使用 PostgreSQL 专属修复状态，保留阶段、原目标、AT 摘要、刷新/同步任务引用、幂等提交键、尝试次数和下次重试时间；不复制 Token。
- 刷新成功后提交定向 C2A 同步，更新前再读取本地当前 AT、远端 ID/邮箱与启用状态，并确认自动移除异常/限流账号两个开关关闭。保留原手动导入的查无则建行为。
- 单次上传回执不明仍保存原始事实；下一轮重新读取原 ID，已写入相同 AT 则确认完成，否则按冷却重新提交当前 AT。普通失败不永久阻断，用户取消的修复不会自动重启，手动立即巡检可再次发起。
- 同一账号存在多个目标时刷新去重，逐个回传原目标。C2A v3.2.9 不接受同一个 AT 归属多个管理 ID；发生冲突时保留原目标并显示明确原因，不以重复登录绕过。处理时复用共享账号租约，账号忙时等待后续扫描。
- 用户补充要求尽量批量：整批分页扫描后一次调度符合条件的账号，刷新和上传任务在已有共享并发预算内并发执行，不等待前一个账号完成才处理后一个。C2A v3.2.9 的新 AT 更新接口只支持单 ID；`batch-update` 只能批量改状态，不得伪造 AT 批量协议。上传并发复用现有 C2A 类型预算；每项独立回执和失败重试。
- 定时巡检默认关闭，默认间隔 300 秒、失败冷却 300 秒、每轮最多处理 500 个账号，配置范围 1–5000；关闭后不发现新修复，已受理阶段继续接续。沿用同一个周期，不新增独立进度轮询任务。
- 配置放在“服务集成 → C2A”，提供开关、间隔、冷却、每轮上限，以及“查看状态”和“立即巡检”；任务中心展示扫描、刷新及同步结果。

## 全局约束

- 不执行 `rm -r` 或 `rm -rf`；不覆盖已有用户修改。
- 不修改任何注册主流程、认证驱动内部步骤和重试策略；只调用现有账号刷新入口。
- 不提交或输出真实账号、密钥、AT、Cookie、OTP、完整代理和运行日志。
- 存储测试使用独立 `turb_test` 数据库和 `PostgresTestCase` 的独立 `test_` schema，通过 `tools/test_isolated.py`。
- 只运行本次客户端、巡检、持久状态、运行时接线、API、配置和界面直接相关测试。
- 提交、推送、部署、服务重启和真实批量修复分开报告；未请求的发布操作不隐含执行。

## 任务 1：C2A 客户端与定向同步

文件：`core/integrations/c2a/client.py`、`manual_sync.py` 和对应集成测试。

提供：

```python
client.list_configured_accounts(*, expected_backend=None, checkpoint=None) -> list[dict]
client.get_account_sync_state(remote_id, email, access_token, *, expected_backend=None, checkpoint=None) -> dict
manual_sync.queue_target(account, remote_id, *, expected_backend, idempotency_key, trigger="c2a_monitor") -> dict
```

列表返回巡检所需的明确字段，不包含凭据。同步状态包含经核对的 `id`、`email`、`enabled`、`token_matches` 和公开状态字段，不返回远端 AT。邮箱不符、原 ID 缺失或被禁用分别报固定原因码。定向任务沿用 `c2a_session_reimport` 与 `c2a_sync` 准入，写入 `remote_account_id` 和 `monitor_managed=True`，不包含 AT。相同 AT 的读回可收口为成功，未匹配时只覆盖原 ID，不新建；原手动调用保持行为。

## 任务 2：持久巡检与修复编排

文件：新增 `core/storage/c2a.py`、`core/integrations/c2a/monitor.py` 和对应测试。

消费任务 1 的接口；内部存储结构由实施者按项目现有锁和事务原语实现。公开提供：

```python
monitor.register_handler()
monitor.run_once(*, force=False, continuation_only=False) -> dict
monitor.status() -> dict
monitor.start_periodic_monitor() -> bool
monitor.stop_periodic_monitor(timeout=2.0) -> bool
monitor.scheduler_status() -> dict
```
