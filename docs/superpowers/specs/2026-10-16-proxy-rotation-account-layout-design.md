# 多国家代理池、出口轮换回收与账号两行布局设计

## 状态与目标

状态：开发实现、综合相关测试和隔离页面验收已完成；服务发布与线上套餐成功率尚未验收。

用户已经明确选择：查套餐允许同一个出口 IP 少量复用，优先考虑速度和成功率。2026-10-16 已通过现有 WebUI 配置入口启用 `PLAN_CHECK_PROXY_ALLOW_REUSE=True`，保留当前默认 `PLAN_CHECK_PROXY_REUSE_LIMIT=3`，包含首次领取。新入队查询采用新配置，已有任务及其重跑继续使用原有配置快照。

本设计回应三个需求：在代理池提供多国家备货入口；账号每条数据最多两行；降低套餐查询因代理缺货、检测争用和出口轮换处理不当造成的失败。注册、补密码、2FA、刷新 AT 和 Codex 的独占租约策略保持原有契约。

## 调查依据与限制

代码基线为 `c782b6d`。2026-10-16 上午的只读数据库、代码和真实浏览器检查发现：

- 最近一批 100 个独立查套餐任务，62 个全部成功、38 个部分成功；35 个任务出现至少一个国家领取代理超时，另外存在 TLS 和 HTTP 403 问题，各类可能发生在同一个任务中。
- 该批次冻结了 `JP / VN / IN`、每国等待 60 秒、禁止复用的策略。当时池配置为空闲底数 20、全局容量 200、worker 5，账号动作并发 10。
- 会话配置为 30 分钟，严格领取后的冷却也是 30 分钟；使用后的资源通常在冷却结束前就过期。
- 当前复检要求出口 IP 与旧锚点完全相同。国家正确、连接正常的新 IP 也会被判为健康失败；隔离状态没有重新探测恢复路径。
- 六条无活跃任务占用的旧线路抽查中，一条已换 IP 且国家匹配，两条仍为原 IP，三条超时。样本接近原到期时间，不能据此推断轮换频率或长期可用性，也不能直接认定它们满足 300 秒的领取剩余寿命。
- 浏览器中的账号表被压缩至 1100px，Token 和账号状态列约 49px，存在内容裁切。`ui-foundation.css` 在 `modern.css` 后加载，布局修改必须同时处理后加载的覆盖规则。

供应商将 `time` 定义为会话时长；该字段不提供“每次提取一定是新 IP”或“检测成功后获得新有效期”的保证。参考 [1024Proxy API 说明](https://help.1024proxy.com/1024/1024proxy/dynamic-residential-traffic/api)。

## 方案选择与范围

采用保留 PostgreSQL 库存、子租约、任务检查点和公平调度的渐进改造。

单纯调大等待时间能够减少部分短期超时，但不能解决出口换代和复检争用；重新建立整套代理平台则会扩大修改范围。首版在现有资源和租约上补齐生命周期，不新增代理平台或任务执行器。

拆成三个可分别验收的部分：配置入口、账号布局、代理生命周期与查询调度。只有最后一部分涉及共享存储与状态迁移，实施时须使用独立工作区及隔离测试数据库或 schema。

## 多国家配置与库存展示

在「配置 → 代理与网络 → 独立代理池」增加 `PROXY_POOL_COUNTRIES`，默认空列表，表示不额外预热国家。支持换行、逗号或空格输入 ISO 两位国家代码，保存时大写、去重并保留顺序。界面名称为“代理池预热国家”。

实际预热 profile 为以下集合的并集，同一来源、配置和国家只建立一份：

1. 默认注册国家对应的现有 profile；
2. `PROXY_POOL_COUNTRIES` 中的额外国家；
3. 独立查套餐实际使用该来源时，`PLAN_CHECK_COUNTRIES` 中的国家。

国家预热只代表准备库存，不会让注册任务自动跨国家。`PLAN_CHECK_COUNTRIES` 继续只决定独立查套餐的业务国家及顺序，入队时冻结。静态池按实际出口筛选并预热，不把同一个 endpoint 同时发布到多个国家 profile。

库存页按国家展示可立即领取、使用中、首次检测、健康复检、等待轮换、故障与最近补货原因。空闲底数仍按活动 profile 计算，全局容量由所有国家共享；界面显示所需空闲底数合计与容量，容量不足时给出明确提示。减少国家或缩小容量不打断已领取任务。

新增配置同步覆盖 schema、模块导出、`.env.example`、现代配置页、README 及配置契约测试。供应商 URL 和密钥继续只保存于 `.env`。

## 出口轮换与回收

### 身份与最少存储变化

`resource_id` 表示持有的供应商 endpoint，`anchor_lease_id` 表示某次检测确认的出口代次。任务子租约继续指向领取时的锚点，已保存的 IP、国家和历史关联不可改写。

增加以下最少状态与字段：

| 位置 | 变化 | 用途 |
| --- | --- | --- |
| `proxy_pool_resources.state` | `rotation_wait` | 无活跃任务时等待出口变化 |
| `proxy_pool_resources.data` | `next_probe_at`、`probe_attempts`、`probe_return_state` | 定时探测、失败限额及中断恢复 |
| `proxy_leases` | `endpoint_owner BOOLEAN NOT NULL DEFAULT TRUE` | 分离 endpoint 所有权与旧出口 IP 隔离 |
| 任务子租约的 `data` | `delivery_state` | 区分领取预留、已交付和确定未交付 |
| 现有字段 | 复用 `owner_token`、`check_deadline`、`reuse_exhausted`、`expires_at` | 并发防护、耗尽及原始寿命 |

endpoint 唯一索引增加 `endpoint_owner=true` 条件；出口 IP 唯一约束保留。所有以 endpoint 判断占用的路径同步识别该字段；旧 IP 的占用、隔离和次数检查不能因此跳过。

需要幂等迁移旧索引，不能仅修改 `CREATE INDEX IF NOT EXISTS` 的谓词并假定已有索引会更新。部署迁移须协调停止旧版本池 worker，避免不同版本同时解释新所有权字段。迁移前完成隔离数据库的升级、重复执行及回滚验证。

### 领取、耗尽和换代

- 每个实际出口 IP 在现有租约有效期统计窗口内最多用于三次查套餐，跨 endpoint、profile 和进程累计。释放及进程重启不清零。
- 第三次领取成功即标记耗尽，并从可用库存统计中移除；已领取子租约正常完成。不得等第四个请求到来才发现耗尽。
- 领取中的预留也参与并发额度。池返回租约前确认未交付的取消，须原子标记 `delivery_state=not_delivered`、返还额度并重新判断当前代是否耗尽；已经交付的查询失败不返还次数。旧子租约缺少该字段时按已交付处理，避免清零历史额度。额度返还不能直接复活过期、故障或检测不新鲜的库存。
- 没有活跃子租约后进入 `rotation_wait`，后台原子取得探测所有权；网络检测在数据库事务外执行。
- IP 未变则继续等待；连接失败或国家不匹配则记录安全原因并退避。连续失败三次，或原始寿命不足以发布时，退役该候选。
- 新 IP 且国家匹配时，在同一短事务内再次检查所有权、原锚点、有效期和无活跃子租约，并检查新 IP 的全局占用与次数。
- 旧锚点变为 `recent`、`endpoint_owner=false`，保留旧 IP 隔离；新锚点取得 endpoint 所有权，使用新 IP 和原到期时间。最后更新资源锚点、清除当前代的 `reuse_exhausted/reuse_exhausted_at` 及探测调度字段，并发布 `ready`。旧代耗尽事实保留在旧锚点或事件中。任一步失败须整体回滚。
- endpoint 和旧、新 IP 的协调锁使用统一顺序；并发换代、两个 endpoint 交换出口等情况不得产生死锁或双重所有权。

普通空闲线路复检发现新 IP，也走上述换代事务。检测期间不能领取；仍有活跃子租约的线路不复检、不换代。检测结果晚到或旧任务晚释放时，通过 token 和原锚点校验阻止改动新代。

明确线路故障进入隔离后，只有在无活跃子租约、原始寿命仍足够时才能转入有界的 `rotation_wait` 探测。保留原故障原因；新出口通过验证后换代，不把仍处于故障隔离的原 IP 直接恢复为可领取。

### 寿命与容量

轮换代次继承最初的 `expires_at`。成功检测只更新观测时间，发布仍要求剩余寿命至少满足 `PROXY_POOL_MIN_TTL`。接近到期时淘汰并交由供应商补货，不通过检测重置为“现在加 30 分钟”。未来如需延长 endpoint 持有期，必须先确认供应商可验证的续租契约，再单独扩展。

等待轮换纳入 endpoint 的全局容量。缺货时可优先退役无活跃子租约、最久未得到新出口的等待资源，为新供应腾出槽位；旧 IP 的隔离历史保留。存量超过容量时只回收空闲资源，正在运行的任务不被驱逐。

### 补货、复检与恢复

保留当前 `PROXY_POOL_WORKERS` 的单进程总 worker 预算，划分独立的补货与复检并发额度：总数大于一时，复检最多占一半向下取整，其余保留给补货；当前五个 worker 对应补货三、复检二。只有一个 worker 时交替处理两类机会，网络请求保持有界。

健康复检和等待轮换探测共用复检额度，各国公平轮转；供应商提取保留现有限速，首次候选检测属于补货额度。复检卡慢不能占用全部补货机会。此预算是单进程预算，多个 WebUI/CLI 进程的库存与资源所有权仍由 PostgreSQL 协调，不能声称本地 semaphore 提供全局并发上限。

定时探测沿用现有检查间隔，并将下次执行时间及累计失败保存在 PostgreSQL。启动恢复处理 `rotation_wait`、过期 `checking`、`fetching` 和 `shared`：中断的检查按原状态重新排入检测，不能直接恢复 `ready`；原有效期已到的资源收口，不复活任务租约。历史严格 cooldown 保持原语义，注册及认证不会因查套餐复用而被提前释放。

## 多国家查询的等待与重试

保留现有任务执行器、Run 和逐国持久化检查点。在 `operation_runs.data.plan_country_progress` 中按国家保存已用领取等待、请求次数、待补试状态、成功状态及原截止时间；账号上的国家结果作为同事务投影，写入仍受当前 Run 执行租约保护。同 Run 的初始化必须幂等，恢复时不得重新将成功国家设为排队或重建截止时间。

首轮每国领取最多尝试五秒（不得超过冻结的单国总等待配置）；缺货先记为本轮待补试，继续其他国家。后续公平轮转未完成国家，累计领取等待不超过原单国配置，所有轮次共用原 Run 总期限。开始领取切片时持久化其开始和截止时间；进程中断后先结算未收口切片，避免重启返还已经消耗的等待预算。

已成功国家立即持久化，本 Run 的内部补试不重新查询成功国家。TLS、代理连接和请求超时等线路错误可在冻结的套餐请求重试次数内换线，释放故障线路并记录原因；同一国家的 HTTP 重试共用持久化次数，不能让每条新线路重新获得完整重试次数。HTTP 401 按账号认证结果处理，HTTP 403 或 429 不进入无限换线重试。

取消和进程重启沿用现有持久任务恢复与租约校验；剩余国家明确收口，成功快照保留。历史任务的手动重跑仍遵守现有配置快照契约。本次不新增需要人工逐个核对的重跑门槛。

## 账号两行布局

保留当前十五列、顺序、筛选标识、批量操作和用户保存列宽。每个单元格最多两条内容轨道，单行内容垂直居中；完整内容通过现有提示和详情访问，不依赖整体裁切形成两行。

| 列 | 第一行 | 第二行 |
| --- | --- | --- |
| 选择、ID、来源 | 原有内容，单行居中 | 留空 |
| 邮箱 / 姓名 | 邮箱 | 姓名及归档标记 |
| Token | 状态及复制入口 | 有则显示异常状态码 |
| 账号状态 | 当前状态 | 简短异常原因 |
| 账号密码 | 复制或未设置 | 留空 |
| 套餐 | 当前套餐 | 提链状态 |
| 额度 | 实际首要窗口，优先 5H | 实际第二窗口，优先周窗口 |
| 套餐优惠 | 有效 Plus 优惠优先的国家结果 | 第二国，或另 N 国及异常统计 |
| 2FA | 启用状态 | 复制验证码 |
| 封号邮件 | 检测状态 | 复查 |
| Codex | 当前状态 | 简短运行或失败摘要 |
| 创建时间 | 日期 | 时间 |
| 操作 | 更多 | 删除 |

桌面默认行高设计起点为 72px，触屏约 80px；最终通过浏览器测量调整，不能缩小现有按钮来满足不够的高度。默认列宽起点依次为 `36/72/160/80/84/88/72/88/88/192/72/88/72/96/108px`，合计 1396px，已通过隔离桌面和手机页面验收。

解除账号表在桌面的 1100px 强制压缩，横向滚动仅发生于现有表格容器，工具栏和分页保持可见。不清空用户保存的列宽及比例；必要时增大整张表，保护 Token、ID 筛选、操作入口及优惠摘要固定标记的必要空间，仅支付方式等可变文案允许截断。极窄历史比例可能导致更宽表格，保留恢复默认入口，不改其他列表的列宽系统。

额度按实际返回窗口选最多两条，优先 5H 和周窗口，不足时由其他窗口补齐，其余窗口进详情。未查询、查询中、失败和未返回窗口继续显示原状态，不凭空构造额度。

优惠为一国时一行、两国时两行；三国及以上第一行显示一个优先结果，第二行显示“另 N 国”，并给失败数、历史数独立的不可裁切标记。同级结果保持配置国家顺序，避免轮询时跳动。全部无优惠或全部待查询，且没有历史快照时，沿用合并展示；全部失败明确显示失败。历史优惠始终带历史标记；长支付方式文案不能挤掉国家和状态。

两行任意一处可进入现有完整浮层；保留全部国家的 Go/Plus、失败原因、历史时间与活动证据，以及悬浮、聚焦、点击、ArrowDown、Escape 和滚动后的定位行为。

## 验证与交付边界

配置与界面先运行最小相关测试，再运行筛选、搜索、分页、IME、优惠和轮询的相邻回归。真实浏览器覆盖 1100/1280/1440px 桌面和 390px 手机，以及默认、保存、拖拽与恢复列宽。优惠覆盖 0/1/2/3/10 国和优惠、失败、历史混合，所有账号行最多两条轨道，复制和操作入口可用。

共享存储改动必须使用项目隔离工具及 `PostgresTestCase`，不得连接生产库运行测试，不得使用 `public` schema。除聚焦和相邻回归外，运行隔离完整测试套件。重点覆盖：

- 同 IP 跨 endpoint 与并发进程合计不超过三次；第三次即撤出可用统计。
- 换代、旧 IP 隔离、不同国家、占用冲突、配额耗尽和原有效期不变。
- 活跃子租约、迟到释放、迟到探测、事务回滚和多 worker 同时探测。
- 领取截止边界的并发取消、确定未交付的额度返还，以及已交付失败不返还额度。
- 原索引迁移、重复迁移、升级旧记录和中断后的启动恢复。
- 复检卡慢时补货仍能推进，等待轮换占满容量时其他国家仍有补货机会。
- 缺货国家内部补试、单国累计期限、总期限、取消及重启后的部分结果保存。

日志及库存只输出安全统计和脱敏信息，不保存或展示完整供应商 URL、账号凭据、Token 和 OTP。运行验收使用少量明确范围的查套餐任务，分别比较领取等待、成功率、供应商提取量和检测量；现有配置生效不能代替这些验收证据。
