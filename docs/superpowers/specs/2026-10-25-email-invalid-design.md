# 邮箱失效标记与派生限制

## 已确认需求

用户要求为原副号4下的全部关联账号增加独立“邮箱失效”标记，并禁止这些邮箱继续派生新的 `+` 子地址。标记依据为原 Apple 账号失控及同组收件抽测异常，不把抽测解释为逐个邮箱均已验证失效。

## 实现范围

- 账号保存独立 `email_invalid` 布尔值及原因、时间、来源、对应邮箱快照；不改变 OpenAI/Codex 封号状态、Token、账号归档和已有任务重跑资格。
- 母邮箱及已有派生地址保存同类邮箱事实，保留邮箱池使用状态、派生账本生命周期及原 Attempt 归属。
- 新领取和新派生排除已失效邮箱，容量预览遵守同一规则；已有领取身份仍能恢复原地址。
- 账号列表在邮箱格显示标记，提供独立筛选及标记/清除入口；“未标记失效”不表示邮箱已验证可用。
- 批量操作按当前邮箱匹配，防止旧快照误标换绑后的新邮箱；普通 AT 写回保留标记，确认换绑按新邮箱重算。

## 方案选择

复用封号会影响账号及 Codex 操作，复用邮箱池 `disabled` 会被同步覆盖，均不符合需求。采用独立邮箱事实，账号高频筛选布尔值提升为 PostgreSQL 列，稀疏诊断元数据保留在 JSONB。

## 验证和上线

存储变更在独立工作区和 `turb_dev` 的 `test_` schema 验证。先运行失败回归，再实现及跑相邻测试、Node 行为测试和真实浏览器验收。完成后整合提交至 `main`，通过原 launchd 重启服务，再用业务 API 为原副号4打标，并核对账号、母资源、子地址数量及其他组未改变。
