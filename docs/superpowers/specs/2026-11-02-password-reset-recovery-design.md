# Roxy 注册续跑的密码重置恢复设计

## 已确认目标

用户于 2026-11-02 明确同意：Roxy 原账号续跑遇到本次密码验证请求明确返回
`password_reset_required` 时，进入已有邮箱重置流程；新密码提交前保存可恢复检查点，
确认后同步账号和原注册任务的密码，再继续资料页，最终核验完整会话和 Token。
手动“修改密码”使用同一套检查点，避免后续注册续跑因新旧密码不一致而中断。

## 现有问题

1. 密码页错误文案识别没有覆盖本轮印地语；网络抓包已收集精确错误码，但执行端未接入。
   失败诊断的中文分类已另行修复，不作为自动改密的历史证据。
2. 手动改密开关在任务数据持久化时被字段过滤规则移除。执行入口已根据
   `password_change` 任务类型恢复语义，不放宽存储脱敏规则。
3. 现有重置 helper 只在重新登录完成后保存新密码，并且不认识资料页；提交后中断可能
   丢失生成的新密码。
4. Accounts 与注册 Attempt 保存各自的密码，一致性校验会拒绝只更新一处的恢复操作。

## 边界

- 自动重置只支持 Roxy 原身份续跑，不为 protocol、proto2 或新注册增加自动改密。
- 触发证据必须属于本次密码提交，匹配派发页面、requestId 和 receipt，并明确为
  HTTP 401、`error.code=password_reset_required`。其他 401、文案、超时和历史抓包不能触发。
- 不删除或放宽现有未决请求、原邮箱、原任务链及身份一致性保护。
- 资料页交接仅表示认证已推进，不表示 Session 成功；完整身份与 Token 验证继续使用原流程。
- 使用 PostgreSQL 的私有持久化能力；候选密码、旧密码不进入普通任务数据、日志和 API 投影。
- 存储实现与测试在独立工作区、非生产测试库及 `test_` schema 中执行。

## 恢复检查点

同账号同邮箱只存在一个未完成的密码恢复记录。记录保存用途受限的私有凭据包及版本，
包含旧密码、候选密码、状态和当前执行归属。候选只生成一次；在新密码输入或点击提交前
完成持久化，保存失败则不派发。状态按 `prepared`、`started`、`unknown`、`confirmed` 记录。

使用独立私有表 `account_password_recoveries`，凭据包加密，不依赖诊断开关，也不随操作历史
删除而级联清除。普通上下文记录和清理行为保持原样。读取和推进必须验证账号、邮箱、
操作 Run 所有权；注册另验证 Attempt、注册 Run、执行身份及其操作映射。注册与操作的
execution_id 分别校验，不能假定二者相同。

确认新密码后，在同一事务内校验旧密码版本，更新 Accounts 与匹配的关联 Attempt，保留
旧密码和恢复事实，保留原 checkpoint 进度。重复确认同一候选幂等，其他密码冲突则保留
检查点并停止，不能任意覆盖。

## 浏览器衔接

复用现有忘记密码、收取新邮件和填写新密码步骤，通过默认关闭的恢复钩子接入检查点。
重置结果须有本次明确响应或使用候选密码的明确登录结果。单纯离开表单不能确认。

重置后已经进入可信、可见的资料表单时交回资料步骤；需要重新登录时使用持久化的候选
密码。重启或显式重跑首先恢复原候选与原提交状态，不重新生成另一份密码。未知状态
继续保留，不误标成功或自动释放邮箱。

## 验证

- 精确密码响应配对：正确响应触发，错目标、错请求、历史响应、其他错误均不触发。
- 私有检查点：提交前保存、失败不点击、候选复用、过期执行拒绝、版本和身份冲突。
- Accounts 与 Attempt 原子同步、回滚、幂等、旧密码保留及普通创建密码保护。
- 浏览器落点：直接资料页、重新登录后资料页、完整 Session；未知结果不确认。
- 中断恢复：提交前后中断均保留候选，重新进入后不重复生成或重复提交未知动作。
- 定向及相邻回归通过后，单账号实跑，以最终完整身份与 Token 为成功依据。
