# 优惠独立存储与筛选设计

用户于 2026-11-26 确认实施独立优惠表、按套餐分组筛选，并要求完成后检查列表刷新效果。本地盘点覆盖 7,796 个账号，保存的优惠为 Team 免费 1 个月，以及 Plus、Go 各自免费 1 个月、半价 1/2/3 个月，共九种。盘点不等于重新查询上游，筛选必须继续保留已有历史成功结果。

## 存储与一致性

新增 `account_promotion_offers` 轻量投影表。每个账号、国家、规范化优惠组合一行，保存 `account_id`、`country`、`offer_key`、`plan`、`kind`、`eligible`、`discount_percentage`、`duration_num_periods`、`duration_period`、`stale`。比例和期限使用 NUMERIC，缺失保持 NULL。国家未记录使用空字符串，不借用注册国家。主键为 `(account_id, country, offer_key)`，额外索引为 `(offer_key, account_id)`，账号删除使用外键级联，归档仍由账号表判断。

投影另存 `legacy_filter_values TEXT[]`，记录原始活动在旧版筛选规则下可匹配的细分类。新组合键按规范化数值和单位合并，旧值继续按原规则匹配；旧字符串期限与数值期限的区别不能在规范化时丢失。同一组合的重复活动合并旧分类，不在热查询中重新解析账号 JSON。

组合键使用 `offer_v1_` 加 32 位小写十六进制摘要，输入是规范化套餐、类型、折扣和期限；同一种权益跨国家或不同 campaign 不分裂选项。具体标题、活动标识、结账信息和原始证据仍保留于既有 JSON 快照。

统一维护投影，覆盖正常套餐保存、直接记录写入、集合导入、兼容写入和版本写入。优先考虑数据库触发器，以最终持久化账号行作为输入，让所有合法写入天然在同一事务生效。更新无关字段不得重写优惠投影；逐国检查点不得提前改变顶层优惠的筛选生效时机。失败保留上次成功结果，成功但不带新优惠字段保留原值，显式空数组清空。保留 none/unknown 的明确事实，不能把没有优惠行当成已确认无优惠。新增明确版本迁移，已有库不重跑旧全表迁移，迁移回填幂等且不请求上游。

## 查询与接口

账号列表、状态轮询、精确总数、联动分面和批量固定名单复用相同的优惠谓词。热查询不得解析账号 `account_promotions` 大 JSON。旧筛选值继续兼容，原 Plus 总类保持原语义；新组合键通过严格格式校验后，以索引查找轻量表。所有属性必须来自同一条优惠，跨国家同种优惠按账号去重。

动态分面通过现有 `facets.promotion` 返回，结构为 `{value, count, label?, group?}`，`group` 使用 `team`、`plus`、`go`、`status`、`legacy`。具体优惠返回组合键、中文完整标签和套餐 group。保留其他列、搜索、日期和归档条件，计算本列时忽略本列自身筛选；已选但无命中的组合保留并显示 0。旧总类或兼容项不与具体优惠重复混排，仅在需要保留已选旧条件时展示。

## 界面

账号和批量创建共用分组与标签逻辑，固定按 Team、Plus、Go、状态、已选兼容条件排序，套餐内免费在前、折扣按比例和期限排序。无优惠明确标注为「Plus 无优惠」，不把它解释为所有套餐无优惠；未查询、失败及历史待复查保留独立状态语义。选项显示去重数量，查询标签显示可读名称，不能显示摘要键。列表的 Team / Plus / Go 标签、提链资格和注册执行行为保持原状。

## 验证与交付

所有数据库测试使用独立 `turb_test` 和 `test_` schema。验证迁移、回填、写入覆盖、失败/缺字段/空数组、跨国去重、旧值兼容、查询与分面/固定名单一致、删除、归档及回滚；前端验证分组、计数、零命中已选条件和可读标签。

性能比较在相同合成数据上交替执行旧 JSON 谓词与新投影谓词，每场景保留 30 个有效样本；另覆盖 30 万合成账号容量档位，旧路径过慢时按发布规则减少旧版容量诊断样本并明确限制。生产服务仅通过授权 GET 记录修改前后实际响应，不以少量诊断样本声称 P95。评审、提交后通过不可变 release 部署本地，保留原主工作区修改，进行健康检查和真实浏览器验收。没有 Oracle 部署或推送授权，不执行对应操作。
