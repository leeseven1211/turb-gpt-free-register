# 幻光支付扫码 CDK 配置

用户需要填写独立的支付扫码 CDK。现有提链 CDK 不能替代该凭据；本次同时连接创建任务时的自动扫码参数，使新配置能够用于实际请求。

## 行为

- 「配置 → 提链 → 幻光」并列显示「幻光提链 CDK」与「幻光支付扫码 CDK」，后者使用 `EXTRACT_LINK_HUANGUANG_PAYMENT_CDK`，默认空值，密码框且仅存 `.env`，不回显、不进入普通快照、任务参数或日志。
- 自动支付默认仍关闭。只有全局、平台的提链及自动支付开关同时开启，并且用户明确选择 `auto_payment`，才在 `/api/checkout` 中提交 JSON 布尔值 `chongyun_auto_submit=true` 及独立的 `chongyun_cdk`。缺少支付 CDK 时不开放自动支付模式，不影响仅提链或手动支付。
- `extract_only`、`manual_payment` 均不提交扫码开关或支付 CDK；外部请求参数不能绕过配置开关或覆盖密钥。
- 扫码由创建接口内置发起，后续读取原任务查询接口，不再创建第二笔扫码订单。保留既有重跑、状态同步、支付与本地 Plus 核验分离的语义。
- 平台扫码完成与 Plus 到账分别判断，不以扫码完成本身宣称到账；敏感凭据需在平台进度和错误信息中脱敏。

## 范围与验证

复用现有配置、运行模式和幻光适配器，不新增支付平台、余额查询、存储结构或自动开启任何设置。使用合成接口与独立测试库验证配置、参数与状态；Chrome 验证输入入口，提交本地 main 并重启 WebUI。用户自行填写密钥，本次不发起真实提链或支付。
