# 第一轮代码阅读整理设计

## 已确认范围

用户已确认第一轮：补齐现有功能地图，拆出提链查询展示代码，按功能块整理账号页脚本。
目标是让维护者从页面或接口找到实际实现及测试，同时保持现有业务行为。

## 提链查询展示

新增 `core/extract_link/workbench_queries.py`，承载工作台任务列表、任务详情、批次列表、
批次详情、候选预览和对应展示投影。`core/extract_link_service.py` 保留原公开函数签名，
将这些查询委托给新模块；创建、取消、执行、支付、重跑、同步和资源管理逻辑留在原位置。
新模块通过现有存储入口读取数据，不反向导入整个业务服务；共享的纯展示规则随投影归位。
不新增配置、不修改 SQL、不改变字段、分页、统计、错误归类或查询次数。

## 账号页脚本

沿用普通静态脚本，保留全局函数、页面结构、事件接口和既有加载顺序。
从 `accounts.js` 抽离任务中心、换邮箱和巡检的完整功能块，分别放入
`account-tasks.js`、`account-email-change.js`、`account-inspection.js`。
账号列表、筛选、详情和原账号操作留在 `accounts.js`。模块顶部说明职责与依赖。
模板在 `accounts.js` 之后、`bootstrap.js` 之前按依赖顺序加载新文件，统一更新本轮脚本
版本号，避免新旧脚本混用。原脚本内的顶层初始化与事件绑定不得重复或丢失。
测试改为读取实际页面加载的脚本组合，既有行为断言继续有效。

## 边界与验证

- 注册主流程、任务执行、重跑策略、并发、事务、锁、启动恢复和数据结构均不调整。
- 不修改现有本地私有数据；不执行递归删除；已有用户修改保留。
- Python 验证通过 `tools/test_isolated.py --profile all -- <定向文件>`，只连接非生产库和
  `test_` schema。先验证查询、状态语义、前端行为、路由及功能地图，再补相邻回归。
- 浏览器验证账号列表/筛选、任务详情、换邮箱弹窗、巡检弹窗和提链工作台的只读交互，
  不为整理验收创建真实批量任务。
- 独立工作区完成审查后合回本地 `main`；分别记录提交、推送、服务重启与真实浏览器验收状态。
