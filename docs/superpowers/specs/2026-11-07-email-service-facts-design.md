# Turb 与 Email Butler 按服务管理邮箱设计

日期：2026-11-07。状态：用户已于 2026-11-07 确认完整方案、实施、验证、提交推送、部署及历史补标；正在实施。本文不代表功能已经上线。

## 已确认的规则

1. 任何完整邮箱地址，只要成功导入过 Turb，永久具有 `openai` 标签。本地和 Oracle 两个实例都适用。
2. 删除邮箱、退号、归档账号、账号封禁、换绑、来源同步和手工编辑标签，都不能清除这个永久事实。
3. OpenAI 服务的新申请不得领取带该标签的地址。其他服务只判断本服务的占用和使用事实，不因 `openai` 标签拒绝领取。
4. Turb 使用已经导入的库存，以及同一任务重跑、超时恢复，是履行原归属；不得被自己的标签拦截。
5. 标签表示曾为 OpenAI 导入或使用，不等同于注册成功。导入、待验证、结果未知和注册成功必须分别保存，不伪造成功次数。
6. 母邮箱、plus 子邮箱和同母兄弟邮箱按完整地址分别记录，不去掉 `+` 后缀合并。

## 当前根因

- Turb 的 `core/storage/email/local_imports.py:import_resources` 只给本地记录默认填充 `service_tags`；调用方传入非空标签时还可能遗漏 `openai`。
- `core/email/email_butler/inventory_handoff.py` 的单项、批量和粘贴导入完成永久交接，但 Butler 没有在同一事务中记录服务导入事实。
- Butler 的 `services/email-butler/app/derived_inventory.py` 用整邮箱的 `available/issued/used` 判断资格；当前归属唯一约束也是一个邮箱一条，而不是一个邮箱一个服务一条。
- Butler 当前主要在成功报告时登记服务标签。Turb 成功记录与报告生成存在分离窗口，部分历史、换绑和导入路径没有成功报告。
- 旧退号会去除未成功使用的 `openai` 标签，已与新确认的永久标签规则冲突。
- 页面用旧来源活动标记判断“已消耗或来源不可用”，与权威库存的来源资格不一致。

## 数据模型

将三个维度分开，PostgreSQL 继续是唯一事实来源。

| 维度 | 拟保存的内容 | 不承担的职责 |
| --- | --- | --- |
| 邮箱资源 | 完整地址、稳定母身份、实际收件路径、禁用/异常/隐藏/明确失效事实 | 不用一个全局 `used` 阻止所有服务 |
| 服务事实 | `address_norm + service`、永久导入标记、历史使用证据、首次事实时间 | 不提供收信授权，不代表当前租约 |
| 服务归属与读租约 | 地址、服务、客户端、原 owner/acquisition、lease、代际、结束时间 | 不因到期或退号删除服务事实 |

### 服务事实及证据

新增 `mail_service_facts`，按 `(address_norm, service)` 唯一。字段包括 `ever_imported`、`imported_at`、`registration_observed_at` 和可选的现有资源关联。

新增 `mail_service_evidence`，按 `(client_id, evidence_id)` 唯一，保存事实类型、完整地址、服务、来源实例、原业务记录引用、事件时间和请求指纹。重复请求返回原回执；相同证据 ID 携带不同内容返回 `service_evidence_conflict`。

`ever_imported` 只允许从假变真；删除资源也保留事实和证据。永久标签从事实派生，与可编辑普通标签合并显示。已有 OpenAI 成功记录同样构成永久排除事实。

事实以完整地址为键，而不是强制引用 HME identity。对于 Butler 没有邮箱素材的历史地址，可以保存服务使用事实，不能借此创建 HME 身份、复制密码或授予收件权限。以后同地址真正进入 Butler 时仍能命中该事实。

### 按服务隔离归属

HME acquisition 增加规范化 `service`；未退回归属的唯一键改为 `(identity_id, service)`。普通 provider 使用对应的按服务归属，不能只修 HME 路径而保留普通 provider 的全局租约覆盖问题。

保持现有 `(client_id, acquisition_id)` 幂等键、全局唯一 `lease_id` 和原代际规则。旧操作的服务从原归属或已保存的客户端策略确定，不能因当前 Key 配置变动而把旧归属迁到其他服务。

`_records`、`_projection`、`snapshot` 必须拆成邮箱总览和指定服务/归属操作视图。不能直接增加多服务 JOIN 后仍按邮箱覆盖单个租约。

## 资格判定与恢复

新申请必须有明确目标服务，由认证后的 Key 策略约束。调用方不能通过改请求中的 `service` 或关闭排除开关，绕过该服务的永久标签。

新申请资格按顺序判断：

1. 邮箱资源满足真实来源条件，未禁用、未异常、未隐藏，也不存在明确转发失效事实。
2. 客户端有权使用该服务和邮箱来源。
3. 该地址在目标服务下不存在永久导入/成功事实、未结束归属或结果未知占用。
4. 其他服务的标签、成功次数和归属不用于拒绝本服务；冷却与失败策略也按目标服务判断。

原任务恢复先用原 `client_id + acquisition_id` 定位，再核对保存的服务、完整地址、owner 和原代际，恢复原读权限，不进入新候选选择。服务不匹配返回 `acquisition_service_mismatch`，不能当作“找不到原意图”而重新领取。未知结果和网络超时保留原意图并允许重跑。

已经显式退号的旧 acquisition 继续保持终止；本设计不复活旧 Token，也不解除已有删除保护。正常运行、未知结果及成功账号的原归属不因永久标签失效。

不同服务可以拥有同一邮箱的独立归属。收码继续使用完整收件人证据、挑战时间和原读取授权，并按目标服务配置发件来源及验证码规则；一个服务的报告、释放和过期处理不能操作另一服务的租约。

当前 HME 的 `icloud_pool.py:fetch_messages_for_api` 会重建取码请求，丢弃上游 `match/service/client/lease`；`automation.py:poll_inbound_code` 的查询仅按地址、时间和验证码筛选。必须显式贯通 `handler → HME adapter → inbound poll` 的可信服务与授权上下文，并在候选选择阶段按服务校验。调用方不能放宽服务的发件来源规则。

永久事实不授予读取权限。普通机器客户端的 address-only resolve/inbound 入口必须校验原客户端、完整地址、服务及 acquisition/读绑定；管理页面的管理员读取权限单独保留。旧固定 profile 没有 acquisition 的读取，在上线前按原 profile 和已有权威身份建立精确、只读的兼容绑定，不能临时新领邮箱、根据当前默认配置猜路径，也不能突然中断现有注册/换绑/刷新 AT 的收码。

## 导入路径

### Butler 管理的邮箱

- 在现有精确交接事务中同时写入服务归属、永久 OpenAI 导入事实和幂等回执。
- 单项、批量、粘贴导入共享同一规则；服务取自可信客户端策略。
- Turb 在确认原完整地址和交接回执后保存本地库存，并始终将 `openai` 并入本地标签集合。
- 远端已完成、本地失败时保留事实和原交接，重试继续原批次/原地址/原 acquisition；不会重新领一批，也不清除标签。
- 重复交接优先返回原意图，不能因自己已写入永久标签而失败。

### 其他来源或历史账号导入

Outlook、通用 API、历史 iCloud/域名库存和“导入为已注册账号”等入口，先保存待同步导入项与服务事实出站事件，不提前发布为已完成导入或可领取库存。

后台发送到专用事实接口，只登记地址及业务证据，不上传邮箱凭据或假造 Butler 收件能力。固定保存目标 Butler、服务、凭据引用和幂等 ID；收到中央事实回执后才原子完成本地导入。失败显示 `pending_sync` 和具体原因，重试原项，进程重启恢复；不终止已有任务或把网络无响应当作远端拒绝。

所有来源的“导入完成”都以中央永久事实已存在为前提，不能依赖 Butler 看不到的本地未发送事件判断资格。新资源进入 Butler 时，资格查询直接连接完整地址的中央事实。同步不可用只让新导入保持待同步，原有库存使用与原任务重跑不增加在线 Butler 检查。

拟新增 `POST /v1/service-facts/batch`：每项包含 `address`、`service`、`fact_type`、`evidence_id`、`source_instance`、`source_record`、`observed_at`；响应逐项给出事实回执或明确错误。批次拆分与重试保留原证据 ID。Key 需有相应事实写入权限和服务范围；历史注册证据导入使用受控对账权限，不能通过普通标签接口伪造成功。

## 删除、退号与标签编辑

删除/退号只终止允许结束的本次占用或读租约，永久 `openai` 标签保持。删除成功的邮箱可以供其他符合条件的服务使用，但不能成为新的 OpenAI 库存。

继续保留已使用、结果未知和运行中身份的现有删除保护。旧退号请求只能返回原回执，不得释放后来产生的租约。

旧退号回执可能包含 `removed=true` 或空 `service_tags`，只作为历史操作结果保留；当前标签必须从永久事实重新读取，不能用旧回执覆盖现状。

Turb 将远端退号意图和返回结果持久化，在后台重试并支持进程重启恢复。本地邮箱池只展示本地删除结果，不提供服务事实同步管理面板。

所有普通标签编辑、独立移除接口、退号、来源快照和兼容导出必须遵守永久事实。试图删除派生永久标签时返回 `permanent_service_tag`，不抹掉历史成功或导入证据。

## 页面展示

Turb 邮箱池是本地导入邮箱的管理页面，支持来自 Butler 或直接导入的素材。这里只展示本地导入、资源状态、使用和删除信息；不展示 OpenAI 服务标签、永久事实、服务同步记录或同步刷新入口。尚未完成导入的资源显示“导入处理中”。以下服务事实和服务可用性由 Email Butler 展示和管理。

邮箱来源状态与服务状态分别展示。服务标签保持 `openai`，详情显示“已导入 Turb（永久）”“已注册”“等待验证/结果未知”等证据，不把标签统一写成注册成功。

按所选服务显示“可新申请/已有永久标签/本服务占用”，并展示具体原因。没有选择服务时，显示来源状态和各服务事实，不输出一个含义模糊的“全局已消耗”。

总览、分页、筛选、候选导入及实际申请共用同一份服务资格判定。删除旧来源活动标记对页面可用状态的误判，保留可核验的明确来源失效事实。

## 历史核对与补标

本地和 Oracle 分别读取原数据库，按完整地址去重并保留环境证据。范围包括：

- 当前及已归档账号；待验证账号另列，不当作成功。
- 已完成注册的 attempt 原邮箱，换绑后的旧邮箱、全部历史分配与本地领取记录；失败/未知任务的已领取地址也不能遗漏，但不标成注册成功。
- 当前邮箱池、`tombstone` 删除记录、成功导入批次中已不在邮箱池的地址。
- Butler 既有服务成功事实和原归属。

提供 `dry-run` 和受控 `apply` 的专用对账接口/工具。`apply` 只单调补充事实及证据，不调用 `report(ok)` 假增成功次数，不重新领取、不续租、不退号，也不修改当前 owner、lease、fence、其他服务或邮箱状态。

明确注册成功的证据可增加 `registration_observed_at` 及证据关联，不重算旧成功次数。仅有导入证据的地址只补永久导入事实。

Butler 无素材的地址登记独立服务事实，并明确显示“无收件资源”；不把这一类混同“已有资源但漏标签”。已有归属不一致时保留归属并在对账结果列出，不通过补标抢占邮箱。

对账错误至少区分：`service_identity_missing`、`service_evidence_conflict`、`service_policy_mismatch`、`service_fact_sync_pending`、`service_fact_delivery_failed`、`permanent_service_tag`。接口报告错误码和可重试属性，不使用未分类错误兜底掩盖原因。

审计范围限于现存持久证据；更早无留痕的物理删除不能推断恢复。两端快照顺序采集，执行前逐项重读证据与归属，不能把一次审计清单当作不变事实。

## 迁移与兼容

1. 新增表、索引和版本化能力声明；独立测试 schema 验证迁移。保留原字段与历史回执。
2. 按原 Key 策略、交接证据、成功标签补齐旧 acquisition 的服务。证据不足时列出迁移冲突，不默认把所有来源都改成 OpenAI。
3. 从两端权威记录生成补标清单，覆盖已退回及仅存导入历史的地址。备份后通过事实接口补充，不手工改兼容文件。
4. 所有领取、恢复、报告、释放和快照都支持服务维度后，再启用同邮箱多服务归属。
5. 旧客户端省略服务时使用已验证的固定策略或原归属；缺少明确服务返回可定位错误。旧请求指纹与回执继续按旧版本识别，避免引入服务字段后旧幂等请求冲突。
6. 多服务数据出现后不能直接启动旧版单归属代码。回滚须停止新写入并使用兼容代码或成套恢复经验证的备份。

## 修改位置与主链路边界

| 仓库/位置 | 具体变化 | 影响边界 |
| --- | --- | --- |
| Turb `core/storage/email/local_imports.py`、`core/email/email_butler/inventory_handoff.py`、`manual_import.py` | 强制本地标签并集，验证远端服务事实，覆盖所有导入入口 | 导入与库存边界 |
| Turb `core/email/email_butler/`、`core/storage/records.py`、`webui/runtime.py` | 服务事实与退号出站事件、分类错误、重启恢复 | 新存储与后台任务；独立工作区和测试库 |
| Turb `webui/routes/email_pool.py`、邮箱页面 | 管理本地导入、状态、使用和删除；远端交互在后台完成 | 本地资源展示及管理 API |
| Butler `app/derived_inventory.py`、`manual_alias_inventory.py`、`automation.py`、`icloud_pool.py`、`utils.py`、`handler.py` | 目标服务资格、多归属、精确恢复/报告/释放、可信服务与收码匹配传递、旧读取绑定兼容 | 会间接改变注册取邮箱与收码，先确认具体方案 |
| Butler `db/migrations/`、`static/app.js`、`static/sources.js` | 新账本迁移与一致的来源/服务状态展示 | 存储迁移和真实浏览器验收 |

本方案不需要修改 Roxy、proto2 等驱动的注册页面、请求参数、步骤、重试与超时。导入时即保存永久事实，不再依赖注册成功报告才有标签；现有成功报告仅用于补充成功证据。修改共享的领取/租约契约仍属于主链路间接行为变化，须按项目约束先确认。

## 验证与交付顺序

1. 独立工作区实施 Butler 数据模型与服务隔离、Turb 导入与同步、页面与对账工具；各自约定接口后并行开发。
2. 最小测试覆盖：导入即永久标记且成功数不变；删除后永久标签仍在；OpenAI 新申请排除；其他服务可领取；同服务并发互斥；跨服务租约互不影响。
3. 验证原意图超时/未知重跑、旧退号重放、旧 Token 失效、来源同步与手工编辑不能抹除永久事实，普通 provider 与 HME 均覆盖。同邮箱两个服务同时 report/release/renew/validate 必须只命中自己的归属；同时收到两种服务邮件时取码不能串用。
4. 迁移和历史补标重复执行幂等；补标前后比对当前归属、租约、代际和统计字段。邮箱素材缺失只新增事实，不创建收件授权。
5. 真实浏览器验证 Butler 页面及目标服务筛选、Turb 本地邮箱导入和删除；隔离环境验证同地址跨服务收码匹配。真实 OpenAI 注册另行明确范围，不把单元测试当线上注册验收。
6. 审查、相关测试及静态检查通过后提交、推送，核对远端提交再部署。生产迁移前备份；本地 Turb、Oracle Turb、Butler 分别核对版本、PID、端口、日志和健康接口。
7. 在已确认补标清单上执行事实补充，复核两端当前账号、历史邮箱和成功导入记录的漏标数；保存私有审计回执，不提交运行数据。
