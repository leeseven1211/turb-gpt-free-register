# 账号贩卖区与多店铺联动第一版

用户已确认贩卖区的待售、已上架、已售出设计，并在完成链动协议验证后明确授权设计开发第一版。本文固定本轮实现边界，不再次发起已授权事项的确认。

## 用户行为

- 账号模块增加「贩卖区」，与活跃账号、归档账号并列。
- 贩卖区提供全部、待售、已上架、已售出筛选，跨页选择、搜索、店铺和来源筛选。
- 活跃和归档账号均可批量加入贩卖区，不自动更改现有归档状态。
- 支持选择店铺和已有商品，批量上架。按 `邮箱----密码----2FA密钥` 交付，不上传 AT、RT 或 Session。
- 上架先保存名单和材料，再在持久任务中执行。外部库存逐条回读确认后标记已上架，创建所属账号来源的归档待办。
- 支持手动标记待售、已上架、已售出及撤销误标，保留事件。改回待售不自动恢复账号活跃，不自动将已发出的材料重新导入。
- 支持店铺、账号来源管理和立即同步；启用的店铺每 60 秒由后台入队同步。鉴权失效只影响该店铺。
- 历史库存先精确匹配来源账号和完整交付资料，再关联商品、库存和订单。歧义、未匹配和外部异常逐项显示具体分类，其余项目继续。
- 商品列表已有两种标识：数值 `goods_id` 与字符串 `goods_key`，均保存。订单状态与发货状态分别处理。

## 模型和约束

销售数据统一存 PostgreSQL。新增销售来源、店铺、商品、库存条目和条目事件表；持久任务复用 `operation_tasks/runs`，不另建绕过共享预算的执行器。

- 来源：`id` 为稳定部署名称，内置 `local`；远端保存 `name/base_url/auth_env`，真实授权码仅位于 `.env`。
- 店铺：`id/name/platform/base_url/token_env/external_shop_id/enabled/owner_id/sync_interval`；第一版适配 `liandong`。Token 仅由环境引用读取，不保存在数据库、列表或任务参数中。
- 商品：按 `(shop_id, external_product_id)` 唯一，另存 `goods_key/name/status/price`。
- 库存条目：按 `(source_id, account_id)` 唯一。展示字段包含邮箱快照、套餐摘要、销售状态、渠道和商品、订单引用、价格、币种、备注、同步和归档状态。
- 材料指纹跨店铺保持唯一；相同内容从不同来源出现时记录冲突，不自动合并或重新销售。
- 外部库存按 `(shop_id, external_inventory_id)` 唯一。订单号按店铺作用域保存，一笔多账号订单只统计一次金额。
- 归档事实与销售状态独立。撤销售出只更改本地标记，不自动撤销发货、恢复库存或取消归档。
- 同步执行端由 `SALES_EXECUTOR_ID` 表示，默认 `local`；每个店铺必须绑定执行端。第一版采用集中销售数据库，不支持跨独立数据库双活。
- 来源身份使用 `(source_id, account_id)`，本地与 Oracle 同号不能互相解释。
- 销售状态为 `for_sale/listed/sold`。内部同步状态、退款事实和归档待办独立，未知平台状态保留具体原因，不冒充成功。

## 联动执行

链动适配器消费已验证的商户后台接口，独立 HTTP 使用 `Merchant-Token`，校验业务码而不只检查 HTTP 状态。适配器返回标准商品、库存和订单结构，不包含公开凭据。

上架请求先事务冻结店铺、商品、条目和交付快照，加密材料复用 `core.storage.runtime_config` 的私有文本加密。任务只保存条目 ID 和目标引用。重复提交、进程中断及超时后，先回读原商品全部库存，按完整材料匹配；已有项确认成功，缺失项才带去重重新导入。整批重复返回 `code=0` 不能单独算失败。重跑不改变原目标和材料。

每次同步分页读取商品、库存和订单。历史订单使用 `goods_key` 验证归属；`status=1` 只表示已付款，实际 `response.cards` 与库存、账号材料一致才标记售出。退款保留已交付归属，记录退款状态，不回库。实际付款时间为 `success_time`；首次观察到已发货另记时间。

精确匹配顺序为既有映射、各来源的当前邮箱唯一候选、完整交付材料核对。无匹配或多来源重复均返回具体问题，不能凭归档或邮箱直接认定售出。

历史同步遍历全部启用来源，不能在本地先命中后跳过其他来源的重复检查。历史库存接管仅建立销售映射，不隐式归档旧账号；用户可批量「标记已上架」明确归档已有库存。新上架仍在确认后自动归档。用于新上架的邮箱、密码和 2FA 三段必须完整且为单行。

外部库存确认与本地归档待办同事务写入。随后调用所属来源的归档 API 并回读；失败保留待办，下轮重试，不回滚真实上架事实。远端归档的批量接口可能返回持久命令，需等待其结果或逐账号归档并读回。

后台 handler 注册进统一任务调度，新增 `sales_sync` 并发策略，默认 1，并继续受全局限制。周期线程只负责生产持久任务，启动、停止和恢复接入受管 runtime manifest。

通用任务恢复只会收口中断的 Run，因此销售启动及周期生产者还须扫描冻结但未确认的上架意图和归档待办，并持久入队后续执行。逻辑意图不变、Run 可新增；仍有排队或有效执行时不重复排队。销售任务使用 `account_id=None`，不将远端账号 ID 带入本地账号租约。

## HTTP 契约

所有接口沿用 WebUI 鉴权。响应 `{ok:true,...}`，异常 `{ok:false,error_code,error}`，不回传 Token、授权码或完整交付材料。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/sales/sources` | 来源列表或新增/修改；请求 `id/name/kind(local或remote)/base_url/auth_env` |
| GET/POST | `/api/sales/shops` | 店铺列表或新增/修改；请求 `id?/name/platform/base_url/token_env/enabled/owner_id/sync_interval` |
| GET | `/api/sales/shops/<id>/products` | 已同步商品 |
| POST | `/api/sales/shops/<id>/check` | 实际鉴权，绑定商户身份，返回能力与商品数量 |
| GET | `/api/sales/items` | `page/page_size/status/shop_id/source_id/q`；返回 `items/total/counts/page/page_size` |
| POST | `/api/sales/items/add` | `source_id/account_ids`；按来源读取资料后加入待售，返回逐项回执 |
| POST | `/api/sales/items/status` | `item_ids/status/channel?/price?/currency?/sold_at?/note?`；保存事件，已上架/售出产生归档待办 |
| POST | `/api/sales/list` | `shop_id/product_id/item_ids/request_key`；持久提交上架任务 |
| POST | `/api/sales/shops/<id>/sync` | `request_key?`；持久提交同步任务 |
| GET | `/api/sales/jobs` | 最近销售任务状态、简要结果和错误分类 |
| GET | `/api/sales/items/<id>/events` | 条目变更记录 |

字段 `product_id` 表示销售商品表本地 ID，适配器调用转换成 `external_product_id`；店铺表 ID 为整数。来源 ID 为稳定短字符串。列表选中 item ID 与账号 ID 不同，不允许混用。

## 第一版界面

独立 Vue 销售组件复用现有列表基础组件、字体、颜色和弹窗样式。账号主列表只新增批量「加入贩卖区」动作，不改注册、认证或现有任务行为。销售页以账号与来源、销售状态、店铺商品、订单与金额、同步状态、操作为主要列。

店铺和来源配置在贩卖区管理弹窗中维护。页面清楚说明环境变量引用及配置状态；不要求用户理解表结构、租约或任务内部字段。

## 验证与交付

先写直接相关测试，存储使用 `PostgresTestCase` 的独立测试库与 schema。覆盖多来源同号、跨店重复、重复上架、回执丢失后回读、部分失败继续、远端归档待办和任务重启。

前端覆盖状态筛选、跨页选择、批量操作与失败呈现，并通过隔离预览服务的真实浏览器验收。不得用测试改生产库或真实店铺库存。无需对注册流程运行无关全量测试。

本轮开发不包含真实扣款、退款执行、其他平台适配器、自动续期商户 Token、Oracle 部署或远端推送。现有链动店铺历史接管和生产上架属于后续明确运行操作，开发验收使用模拟店铺和隔离数据库。
