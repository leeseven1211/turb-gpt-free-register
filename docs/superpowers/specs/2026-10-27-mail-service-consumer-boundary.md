# 邮箱服务与 Turb 使用边界

用户已明确要求全面审查并隔离邮箱链路：邮箱服务负责管理和运维，Turb 只导入及使用；大部分后续邮箱由 Email Butler 提供，也允许直接导入购买的短效邮箱。本设计执行这项现有授权。

## 职责

邮箱服务负责母号、凭据运维、创建/同步/子邮箱生成及上游库存管理。Turb 保存人工导入的完整邮箱、固定收码连接、有效期、唯一业务归属、OTP 身份隔离和使用结果。Turb 的新发号只访问本地五池，空库存直接提示导入；无后台自动补号、续购、恢复时换号或推测收件目标。

Turb 的管理类 HTTP/API 和直接客户端创建/同步函数明确退役；配置保留历史读取，编辑页仅保留消费者所需的连接和等待设置。历史已购买订单只恢复已有订单，不产生新购买。账号邮箱失效是 Turb 的业务事实，不能推断整个上游邮箱服务被永久删除。

## 使用结果与邮箱服务解耦

本地使用结果与需要同步的 Butler 使用回执在同一 PostgreSQL 事务提交。网络报告由持久 outbox 重试，采用稳定 operation_id、原固定连接和显式 service/consumer，不把第三方超时变成注册失败，不因重启重复发放地址。未知注册结果不报告成功、不释放原占用。旧 Butler HME 结果回写也进入同一队列；不盲目重试缺少幂等契约的旧普通租约变更。

## 短效邮箱

现有 Outlook 四段和通用 API 两段格式保持。通用 API 额外支持第三段显式带时区的 expires_at；导入预览验证时间，不从 token 或域名猜有效期。过期或无效时间不能被计为可领取；领取时在数据库再次检查；原任务恢复和取码也检查有效期，过期保持原领取事实并明确报错，不换邮箱。

结构化响应中存在的收件地址或时间是约束，拒绝后不能退回全文正则重新提取旧码。纯文本短效接口继续兼容，但不声称有原始收件证据。错误和日志不暴露取码 URL、Token、验证码或邮件正文。

## Butler 后续接入契约

当前严格 HME 固定收码继续工作。普通 Butler 五段账号导出缺少身份、授权、收码连接和期限，不能直接视为可用消费包；其他 provider 须具备明确的固定读取身份和有效期才能导入，不能伪装为 HME。将现有契约缺口记录为独立可实施的消费包规范；本次不把缺少授权/身份的数据偷偷启用。

## 验证与发布

隔离测试仅使用 mail_prepare_20261027 临时 schema；不在生产 public 做开发测试。覆盖退役入口无外部请求、过期领取/重入、结构化旧码/收件人拒绝、outbox 事务性/重放/断网/重启、固定 profile、现有账号空库存仍可收码和扫描。生产发布需备份、两次空闲门禁、保留所有业务数据与历史凭据；不执行 rm -r，不 push。
